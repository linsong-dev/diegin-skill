# 沙漏 · Shalou · 流动的记忆

## 开发文档 · 封笔终稿

---

Shalou 是迭进的记忆壳。它承载的不仅是静态数据，更是持续流动的认知——规则在流动中激活，模式在流动中沉淀，方向信号在流动中翻转。迭进驱动流动的方向，Shalou 记录流动的内容。

Shalou 是迭进沙漏架构的**壳体**，与迭进（核心原则层）共同构成完整的认知操作系统。


## 一、命名与定位

### 1.1 正式名称

**沙漏 · Shalou · 流动的记忆**

- **简称**：Shalou
- **英文引用**：Shalou · Flowing Memory
- **系统缩写**：SL

### 1.2 在迭进沙漏架构中的定位

| 维度 | 迭进 | Shalou |
|:---|:---|:---|
| **角色** | 沙漏的中心点（动态流动方向） | 沙漏的壳体（静态存储介质） |
| **职责** | 判断、驱动、学习、纠错、裁决、审视 | 存储、检索、归档、维护 |
| **状态** | 动态运行（每次交互拉起） | 静态持久化（文件/数据库） |
| **产出** | 规则、模式、信号、决策指令 | 结构化存储、语义检索、状态恢复 |

Shalou 不是迭进的可选插件，而是迭进持续运行的必要基础设施。没有 Shalou，迭进的任何原则都无法跨轮持续运行。

### 1.3 Shalou 与迭进的接口边界

Shalou 与迭进通过**接口层**交互，不直接访问对方内部状态：

| 交互方向 | 内容 | 触发方 |
|:---|:---|:---|
| 迭进 → Shalou | 写入规则、模式、封存包、信号、审计记录 | 攻七/守三/恒常门/止观门/自照镜/持行章 |
| 迭进 ← Shalou | 按需加载规则、语义检索记忆、恢复任务状态 | 预策律/自照镜/恒常门/持行章 |


## 二、存储架构

### 2.1 存储空间总览

Shalou 包含以下十一个核心存储空间，用于承载迭进各原则产出的认知资产：

| 空间 | 存储内容 | 写入方 | 读取方 | 保留策略 |
|:---|:---|:---|:---|:---|
| **rule** | 守三/一二不过三产出的纠错与阻断规则 | 守三、一二不过三 | 预策律、持行章 | 永久保留（除非人工清理） |
| **pattern** | 攻七产出的成功模式 | 攻七 | 预策律、守三 | 永久保留（除非人工清理） |
| **trade** | 交易/领域相关的规则包（可插拔） | 通外·纳新 | 预策律（按域加载） | 随领域规则包生命周期 |
| **abstract** | 举一反三产出的高阶泛化规则 | 举一反三 | 预策律 | 永久保留（除非人工清理） |
| **goal** | 目标进度快照（不可被P6调权影响） | 恒常门、止观门 | 预策律、一二不过三、自照镜 | 永久保留（目标完成后归档） |
| **case_prototype** | 叙事类比通道沉淀的案例原型 | 去伪存真 | 守三（原型转规则检查） | 50轮或7天（可配置） |
| **anomaly_vault** | 单次极端成功案例（突变实验舱） | 自照镜、去伪存真 | 自照镜（轻量校准比对） | 30天（超时自动淘汰） |
| **codex** | 封存包、执行轨迹、自照报告 | 恒常门、止观门、自照镜 | 守三（应急复盘）、自照镜 | 30天（超时冷存储） |
| **raw_chat** | 原始对话记录 | 系统自动 | 预策律（仅限方向预判） | 按系统清理策略 |
| **state** | 系统运行时状态标志 | 迭进引擎 | 迭进引擎 | 实时更新 |
| **verification** | 去伪存真验证结论 | 去伪存真 | 守三、自照镜 | 90天或1000条 |

### 2.2 anomaly_vault（突变实验舱）说明

**触发条件：** 单次成功案例，其置信度异常高（>4.8）且历史相似场景成功率<30%（即"出乎意料的成功"）。

**入舱后行为：**

- 自照镜在轻量校准模式中，强制比对当前环境与舱内案例的环境特征（余弦距离）
- 若高度相似（>0.8），直接生成一次性"探险信号"注入P4裁决，绕过3次验证门槛
- 探险信号有效期为当前轮次，不累积
- 入舱记录保留30天，超时自动淘汰

**守三冲突处理：**

- 当注入探险信号并执行时，临时挂起守三对该轮次该行为的strike记录（仅挂起，不丢弃）
- 待轮次结束后，根据最终目标完成度判定该轮是"英明冒险"还是"壮烈牺牲"，再决定是否将strike记录归档
- 若轮次成功，该strike记录永久丢弃
- 若轮次失败，该strike记录正常归档，供守三复盘使用


## 三、空间定义与数据格式

### 3.1 rule（规则空间）

存储守三产出的纠错规则与一二不过三产出的阻断规则。

```json
{
  "id": "rule_<timestamp>_<hash>",
  "type": "corrective | blocking",
  "source": "守三 | 一二不过三",
  "trigger_condition": "当<条件>时触发",
  "action": "执行<动作>",
  "confidence": 4.2,
  "history": [
    {"event": "created", "timestamp": "...", "confidence": 4.2},
    {"event": "adjusted", "timestamp": "...", "confidence": 3.8, "reason": "守三下调"}
  ],
  "goal_id": "goal_<hash>",
  "domain": "trading | writing | coding | research | general",
  "created_at": "2026-09-07T10:00:00Z",
  "updated_at": "2026-09-07T10:00:00Z",
  "active": true,
  "activation_count": 0,
  "miss_count": 0
}
```

### 3.2 pattern（成功模式空间）

  "success_context": "在<场景>下，执行<操作>成功",
  "key_factors": ["因子1", "因子2"],

## 五、检索机制

### 5.1 语义检索

Shalou 支持按语义相似度检索记忆，用于预策律的"衡"阶段：

- 输入：查询文本 + 目标空间列表 + 相似度阈值
- 输出：按相似度排序的记忆列表（最高20条）
- 相似度计算方式：余弦相似度（默认阈值≥0.6）

**语义映射版本锁定**：当底层向量模型升级时，强制触发语义映射版本锁定。新旧版本并存期（默认7天）内，新索引与旧版本并行运行，比对两者在同一查询下的召回率差异。若差异超过阈值（如余弦距离>0.15），则阻断升级并通知人工介入。

### 5.2 按域加载

Shalou 支持按领域定向加载规则，用于预策律的"按需加载"：

- 输入：domain（trading/writing/coding/research/general）
- 输出：该域下所有 active=true 的规则/模式
- 加载上限：50条（超过则按置信度排序截断）

### 5.3 按目标聚合

Shalou 支持按 goal_id 聚合所有相关记忆：

- 输入：goal_id
- 输出：该目标下所有规则、模式、任务、快照的聚合视图
- 用于：自照镜审视目标进度、一二不过三目标熔断、预策律带goal维度裁决


## 六、保留与清理策略

### 6.1 各空间保留策略

| 空间 | 保留期 | 清理条件 | 清理动作 |
|:---|:---|:---|:---|
| rule | 永久 | 人工清理或置信度=0 | 归档至冷存储 |
| pattern | 永久 | 人工清理 | 归档至冷存储 |
| abstract | 永久 | 支撑度<0.3 | 标记为abandoned |
| goal | 永久 | 目标完成后归档 | 状态置为completed |
| trade | 随领域规则包 | 规则包卸载 | 整体移除 |
| case_prototype | 50轮或7天 | 超时未触发规则化 | 自动淘汰 |
| anomaly_vault | 30天 | 超时 | 自动淘汰 |
| codex | 30天 | 超时 | 自动转冷存储 |
| verification | 90天或1000条 | 超期或超量 | 自动压缩为月度摘要 |
| state | 实时 | 状态变更 | 覆盖更新 |

### 6.2 自动清理触发时机

- **深度复盘时**：守三触发深度复盘时，同步扫描过期数据
- **入口检查时**：持行章在入口检查时检测存储占用
- **批处理窗口**：举一反三板处理时同步执行清理

### 6.3 冷存储管理

codex 空间保留最近30个任务的快照全集；更早的快照仅保留核心字段（task_id、intent_summary、status、completion_criteria），完整快照归档至冷存储。冷存储数据不参与实时检索，可手动恢复。


## 七、运维接口

### 7.1 健康检查

Shalou 提供以下健康检查指标：

| 指标 | 说明 | 健康阈值 |
|:---|:---|:---|
| 存储占用率 | 总存储量/预设容量 | ≤80% |
| 检索延迟 | 语义检索平均耗时 | ≤500ms |
| 写入延迟 | 写入操作平均耗时 | ≤100ms |
| 空间分布 | 各空间记录数 | 无异常集中 |
| 过期比例 | 过期未清理记录占比 | ≤10% |

### 7.2 读写流量监控

Shalou 提供读写操作的流量统计：

- 总写入次数（按空间）
- 总读取次数（按空间）
- 各原则调用频次
- 高负载时段识别

### 7.3 备份与恢复

- **每日自动备份**：完整备份（含所有空间）
- **增量备份**：每6小时（仅变更数据）
- **恢复点**：保留最近7天的备份点

**工程实现阶段已知关注项：**
1. 快照实际大小：16k tokens为建议上限，执行轨迹快照可能远超此值，需在实现时评估实际大小并确定冷存储转换阈值。
2. 语义检索延迟：规则库达到1000条以上时，500ms健康阈值可能守不住，需在实现时进行性能测试并预留优化路径。
3. 状态标志生命周期：攻七/守三的状态隔离标志需定义异常恢复路径，防止异常中断导致标志永久置位。
