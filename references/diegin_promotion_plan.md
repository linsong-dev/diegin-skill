## 一、迭进是什么（30 秒简介）

迭进（Diegin，DGEN）是一套 **AI 全域常驻的自我迭代进化系统**。它不绑定任何模型、平台或业务场景，以 **律令九章**（四律三门一锁一镜）为内核，让 AI 具备：

- **自主纠错**（守三：负向拦截 + 深度复盘）
- **自主强化**（攻七：识别成功 → 提炼模式 → 主动写入）
- **自主记忆**（一二不过三：三错锁 + Mindol 语义记忆后端）
- **自主进化**（举一反三：跨域泛化 + 去伪存真验证）

### 律令九章原则网络（v3.9.4）

| 章 | 别名 | 方向 | 一句话 |
|:--|:--|:--|:--|
| 攻七 | 行知律 | 正向强化 | 试之以行 → 成则炼之 → 通则固之 → 泛而验之 → 废则舍之 |
| 守三 | 省知律 | 负向纠错 | 失则拆之 → 拆则溯之 → 溯则炼之 → 炼则铭之 → 铭则复战 |
| 一二不过三 | 三错锁 | 安全阀 | 初犯立改验 → 再犯锁其途 → 三犯剑落下 |
| 举一反三 | 通变门 | 跨域泛化 | 从个案提炼通则，回归校验 |
| 去伪存真 | 真伪门 | 真伪验证 | 规则/模式生效前过滤，避免自欺 |
| 预策 | 裁决律 | 权衡决断 | 汇而衡之 → 预而策之 → 决而行之 → 复而平之 |
| 持存 | 恒常门 | 任务续接 | 启而探之 → 行而记之 → 断而存之 → 续而接之 |
| 止观 | 完形律 | 完形封存 | 事毕清零，防追加纠错内耗 |
| 自照镜 | 方向之镜 | 自我审视 | 照见方向，不复迷失 |

> **执行优先级 P0-P6**：P0 去伪存真无条件优先；P1 一二不过三阻断优先；P2 完形律清零优先；P3 恒常门任务恢复优先；P4 守三/攻七置信度裁决；P5 staging 不参与实时；P6 Mindol 语义权重仅影响 P4 与兜底（调权 ±0.3，单轮 ±0.1）。

### 工程形态（可运行、已落地）

- **引擎**：纯 Python + PowerShell 钩子，常驻于 Codex 会话（PreToolUse / PostToolUse / SessionStart / Stop 全链路）
- **规则库**：规则总数与活跃数见 `references/metrics_2026-08-24.json`（2026-08-24 实测；自检 16/16 全绿、测试 33/33）
- **记忆**：Mindol 语义记忆引擎（内存检索 ~2ms，SQLite 仅持久化，save 性能优化 21x；记忆单元数见 `references/metrics_2026-08-24.json`）
- **协议**：A 方案（DGEN 状态显示）+ B 方案（标记状态机 pending→allowed→verified 审计闭环）
- **自保护**：BOM 编码修复、pre_tool 自阻断循环修复、铁墙规则（连续拦截 ≥3 升级）

## 二、与主流方案的对比（LOOP / 目标模式）

### 2.1 迭进 vs LOOP（当前流行的循环模式，如 Reflexion 等）

| 维度 | LOOP 类循环模式 | 迭进 DGIN |
|:--|:--|:--|
| 本质 | 单轮「执行→反馈→反思→再执行」的循环模板 | 常驻进化层：律令九章 + 引擎 + 记忆 + 钩子 |
| 记忆 | 依赖对话上下文/外部向量库，循环结束即散 | Mindol 语义记忆持久化，跨会话长期沉淀 |
| 纠错 | 反思后重试（同一层面反复） | 守三拦截 + 一二不过三升级（阻断→固化→通知用户） |
| 强化 | 弱（只反思失败，很少固化成功） | 攻七成功模式提炼 + 举一反三泛化 + 去伪存真验证 |
| 仲裁 | 无/隐式 | 预策·裁决律显式仲裁规则冲突（P0-P6 硬优先级） |
| 调度 | 无 | 预策·裁决律统摄权衡 + 止观·完形律事毕封存 |
| 依赖 | 常需 LLM API / 外部服务 | 纯本地、零外部 API、numpy 即可 |
| 层次 | 方法/模板（战术） | 操作系统级进化层（战略） |

**结论**：LOOP 解决「这一次怎么做好」，迭进解决「AI 长期怎么越来越好」。迭进可以容纳 LOOP 作为其中一种执行循环。

### 2.2 迭进 vs Codex 目标模式（goals）

| 维度 | Codex 目标模式 | 迭进 DGIN |
|:--|:--|:--|
| 本质 | 平台级任务管理（目标/预算/延续） | 认知进化层（规则/记忆/裁决） |
| 作用面 | 单线程任务的推进与续跑 | 全会话、全工具调用的质量与进化 |
| 失败处理 | 任务中断/超时由平台控制 | 守三拦截 + 一二不过三三错锁 + 铁墙升级 |
| 成功沉淀 | 不沉淀 | 攻七自动提炼成功模式（已与 create_goal/update_goal/get_goal 联动，见成功模式库） |
| 记忆 | 无 | Mindol 长时记忆 + 规则库 + 模式库 |
| 关系 | 迭进在目标模式之上运行 | 目标模式是迭进的「任务载体」之一 |

**实证**：引擎成功模式库中已存在 pat_auto_tool_create_goal_1、pat_auto_tool_update_goal_1、pat_auto_tool_get_goal_1，证明迭进已真实在 Codex 目标模式会话中工作并沉淀成功经验。

### 2.3 三者关系一句话

> **目标模式 = 导航（要去哪）；LOOP = 驾驶动作（怎么开）；迭进 = 车载进化系统（越开越稳、越开越聪明、错不重犯）。**

## 三、迭进的优势

1. **九章闭环完整**：行知·攻七（强化）+ 省知·守三（纠错）+ 三错锁（底线）+ 通变门（泛化）+ 真伪门（验证）+ 预策（权衡）+ 恒常门（续接）+ 完形律（封存）+ 自照镜（方向），互为补充交叉，无单点断链
2. **解决「AI 记不住」痛点**：用对的方法会忘？→ 攻七把成功模式写入规则库；错会重复？→ 一二不过三从立改到硬阻断到升级
3. **纯本地零依赖**：无 API Key、无 GPU、无网络；SQLite + numpy 即可；数据不出本地
4. **跨平台场景无关**：编码、分析、创作、定时任务、子会话全覆盖（系统级规则 + 可插拔领域规则包）
5. **可观测可审计**：DGEN 状态文件、审计日志、strike 记录、成功模式库，全程可查
6. **工程级健壮**：BOM 编码、自阻断循环、铁墙、空上下文兜底等自保护机制（v3.6.x 实战修复验证）
7. **已与生态融合**：Codex 钩子全链路、插件市场（personal marketplace）、目标模式联动、mindol 记忆后端

## 四、迭进解决的问题（痛点对照）

| 痛点 | 迭进的解法 |
|:--|:--|
| AI 重复犯同样的错 | 一二不过三：立改→加固阻断→三错升级通知 |
| AI 记不住用对的方法/工具 | 攻七：成功模式自动提炼、注入、复用 |
| 长任务频繁中断 | 钩子状态机 + 恒常门断而存/续而接 + 目标模式续跑（跨对话可恢复，恢复率实战验证中） |
| 规则冲突/自相矛盾 | 预策·裁决律仲裁（P0-P6）+ 去伪存真过滤 |
| 上下文超限丢失经验 | Mindol 语义记忆 + 规则/模式库持久化 |
| 深度复盘拖慢紧急任务 | 预策·裁决律轻重分流 + 止观·完形律事毕清零 |
| 无法证明 AI 是否真在进化 | 规则数/模式数/拦截数/审计日志可量化追踪 |

### 效果衡量与评估（KPI，2026-08-25 新增）

> 首次基线已建档：`references/promotion_kpi_baseline_2026-08-25.md`（三平台 9 组数据 + 账号级数据 + 文章链接）。评估原则：**先建档，再评估**——没有基线就谈不上「有效果/没效果」。

**四层 KPI，对应四个问题：**

| 层 | 回答的问题 | 指标 | 观测时点 |
|:--|:--|:--|:--|
| 过程层 | 有没有按计划执行 | 发文量/节奏、三平台覆盖、门禁通过率、版本同步及时性 | 随时 |
| 触达层 | 有没有人看到 | 阅读量、完读率、搜索引擎收录 | 发布后 7 天 |
| 互动层 | 看到的人觉得有没有用 | **收藏率**（收藏/阅读）、点赞、实质评论数 | 14–30 天 |
| 转化层 | 有没有人真去用 | **GitHub star**、插件安装量、主动联系/issue/求 demo | 30–90 天 |

**判断逻辑（核心）：**
- **收藏率 = 内容质量信号；阅读量 = 流量信号；star = 转化信号。**三者分开看，不混成一个「反响」。
  - 阅读低 + 收藏率高 → 内容有价值，是渠道/流量问题 → 换标题、做 SEO、换平台首发
  - 阅读低 + 收藏率低 → 内容表达问题 → 优化开头/标题/结构
  - 收藏高 + star 涨 → 真有效果，可加推
- 「迭进有没有价值」由**收藏率和 star** 回答，不由阅读量回答。
- 技术文冷启动周期 2–4 周；CSDN 搜索长尾 30 天后才进入增长期。**7 天看触达、30 天看互动、90 天看转化**，不用同一把尺子量所有阶段。

**合理基准（无大V冷启动）：**
- 阅读：掘金 100–500 / CSDN 50–300（搜索长尾持续涨）/ 知乎 50–200
- 收藏：掘金 5–20 / 知乎 2–10；收藏率 2% 附近为「有用但未惊艳」，>5% 为「强价值内容」
- 实质评论 0–3 条正常；「这跟我用的 XX 差别在哪」类评论反而是好信号

**执行节奏：**
- 每次发布后 7 天建档一次（触达层）
- 每 30 天全量对比基线（互动层 + 转化层），输出「推广效果月报」
- 90 天做一次「内容矩阵取舍」：阅读低+收藏低且无转化 → 停更该方向，聚焦有效方向
