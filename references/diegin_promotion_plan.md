## 一、迭进是什么（30 秒简介）

迭进（Diegin，DGEN）是一套 **AI 全域常驻的自我迭代进化系统**。它不绑定任何模型、平台或业务场景，以 **八元原则网络** 为内核，让 AI 具备：

- **自主纠错**（守三：负向拦截 + 深度复盘）
- **自主强化**（攻七：识别成功 → 提炼模式 → 主动写入）
- **自主记忆**（一二不过三：三错锁 + Mindol 语义记忆后端）
- **自主进化**（举一反三：跨域泛化 + 去伪存真验证）

### 八元原则网络（v3.6.6）

| 原则 | 方向 | 一句话 |
|:--|:--|:--|
| 守三 | 负向纠错 | 检测错误、拦截风险、深度复盘 |
| 攻七 | 正向强化 | 成功模式提炼与固化（不重犯 → 更要用对） |
| 一二不过三 | 三错锁 | ①错立改+改毕验 → ②再错加固阻断 → ③三错升级处理 |
| 举一反三 | 跨域泛化 | 从个案提炼通则，回归校验 |
| 去伪存真 | 验证 | 规则/模式生效前过滤，避免自欺 |
| 裁决律 | 仲裁 | 规则冲突时按置信度/优先级裁决 |
| 缓急律 | 调度 | 紧急走快通道，常规走完整流程，设宕机时段 |
| 止观门 | 收尾 | 事毕清零，防追加纠错内耗 |

### 工程形态（可运行、已落地）

- **引擎**：纯 Python + PowerShell 钩子，常驻于 Codex 会话（PreToolUse / PostToolUse / SessionStart / Stop 全链路）
- **规则库**：261 条拦截规则 + 30 条成功模式（实测）
- **记忆**：Mindol 语义记忆引擎（内存检索 ~2ms，SQLite 仅持久化，save 性能优化 21x）
- **协议**：A 方案（DGEN 状态显示）+ B 方案（标记状态机 pending→allowed→verified 审计闭环）
- **自保护**：BOM 编码修复、pre_tool 自阻断循环修复、铁墙规则（连续拦截 ≥3 升级）

## 二、与主流方案的对比（LOOP / 目标模式）

### 2.1 迭进 vs LOOP（当前流行的循环模式，如 Reflexion 等）

| 维度 | LOOP 类循环模式 | 迭进 DGIN |
|:--|:--|:--|
| 本质 | 单轮「执行→反馈→反思→再执行」的循环模板 | 常驻进化层：八元原则网络 + 引擎 + 记忆 + 钩子 |
| 记忆 | 依赖对话上下文/外部向量库，循环结束即散 | Mindol 语义记忆持久化，跨会话长期沉淀 |
| 纠错 | 反思后重试（同一层面反复） | 守三拦截 + 一二不过三升级（阻断→固化→通知用户） |
| 强化 | 弱（只反思失败，很少固化成功） | 攻七成功模式提炼 + 举一反三泛化 + 去伪存真验证 |
| 仲裁 | 无/隐式 | 裁决律显式仲裁规则冲突 |
| 调度 | 无 | 缓急律紧急分流 + 止观门收尾 |
| 依赖 | 常需 LLM API / 外部服务 | 纯本地、零外部 API、numpy 即可 |
| 层次 | 方法/模板（战术） | 操作系统级进化层（战略） |

**结论**：LOOP 解决「这一次怎么做好」，迭进解决「AI 长期怎么越来越好」。迭进可以容纳 LOOP 作为其中一种执行循环。

### 2.2 迭进 vs Codex 目标模式（goals）

| 维度 | Codex 目标模式 | 迭进 DGIN |
|:--|:--|:--|
| 本质 | 平台级任务管理（目标/预算/延续） | 认知进化层（规则/记忆/裁决） |
| 作用面 | 单线程任务的推进与续跑 | 全会话、全工具调用的质量与进化 |
| 失败处理 | 任务中断/超时由平台控制 | 守三拦截 + 一二不过三三错锁 + 铁墙升级 |
| 成功沉淀 | 不沉淀 | 攻七自动提炼成功模式（已与 create_goal/update_goal/get_goal 联动，见成功模式库） |
| 记忆 | 无 | Mindol 长时记忆 + 规则库 + 模式库 |
| 关系 | 迭进在目标模式之上运行 | 目标模式是迭进的「任务载体」之一 |

**实证**：引擎成功模式库中已存在 pat_auto_tool_create_goal_1、pat_auto_tool_update_goal_1、pat_auto_tool_get_goal_1，证明迭进已真实在 Codex 目标模式会话中工作并沉淀成功经验。

### 2.3 三者关系一句话

> **目标模式 = 导航（要去哪）；LOOP = 驾驶动作（怎么开）；迭进 = 车载进化系统（越开越稳、越开越聪明、错不重犯）。**

## 三、迭进的优势

1. **八元闭环完整**：负向纠错 + 正向强化 + 三错锁 + 泛化 + 验证 + 仲裁 + 调度 + 收尾，互为补充交叉，无单点断链
2. **解决「AI 记不住」痛点**：用对的方法会忘？→ 攻七把成功模式写入规则库；错会重复？→ 一二不过三从立改到硬阻断到升级
3. **纯本地零依赖**：无 API Key、无 GPU、无网络；SQLite + numpy 即可；数据不出本地
4. **跨平台场景无关**：编码、分析、创作、定时任务、子会话全覆盖（系统级规则 + 可插拔领域规则包）
5. **可观测可审计**：DGEN 状态文件、审计日志、strike 记录、成功模式库，全程可查
6. **工程级健壮**：BOM 编码、自阻断循环、铁墙、空上下文兜底等自保护机制（v3.6.x 实战修复验证）
7. **已与生态融合**：Codex 钩子全链路、插件市场（personal marketplace）、目标模式联动、mindol 记忆后端

## 四、迭进解决的问题（痛点对照）

| 痛点 | 迭进的解法 |
|:--|:--|
| AI 重复犯同样的错 | 一二不过三：立改→加固阻断→三错升级通知 |
| AI 记不住用对的方法/工具 | 攻七：成功模式自动提炼、注入、复用 |
| 长任务频繁中断 | 钩子状态机 + BOM/循环修复 + 目标模式续跑（本对话实测修复后全程未中断） |
| 规则冲突/自相矛盾 | 裁决律仲裁 + 去伪存真过滤 |
| 上下文超限丢失经验 | Mindol 语义记忆 + 规则/模式库持久化 |
| 深度复盘拖慢紧急任务 | 缓急律紧急分流 + 止观门事毕清零 |
| 无法证明 AI 是否真在进化 | 规则数/模式数/拦截数/审计日志可量化追踪 |

## 五、应用前景

1. **个人 AI 工作流**：每个 Codex 用户的常驻进化层，越用越懂你
2. **团队/企业知识沉淀**：领域规则包 + 共享规则库，把团队最佳实践固化成引擎规则

4. **自动化与定时任务**：全场景接入规范（DGEN_GLOBAL_ACCESS），输出质量可控
5. **AI 安全与治理**：拦截高风险操作、成本不透明阻断、审计日志（守三 + 铁墙）
6. **教育与研究**：八元原则网络可作为 AI 自我进化方法论的教学框架

## 九、攻七强化与系统净化（2026-08-05 实施）

### 攻七强化（v3.8，四条链路）
- **及时使用**：pre_check 高置信度模式（conf≥4.5）标 priority，display_line 升级 `✅ 攻七优先采用`
- **优先选用**：仲裁器 P4 同场景加权 +0.5（同工具复用验证过的方法优先于负向纠错；不凌驾 P0-P3）
- **泛化提速**：generalize_from_patterns 门槛放宽为「复用≥2 次 或 conf≥4.5」（复用即验证信号）
- **反馈闭环**：feedback_adopt（adopt +0.5 / veto ×0.7）+ post_tool 自动采纳

### 系统净化（质量护栏，防再生）
- 攻七：28 条空壳模式归档（audit_patterns），保留 6 条实质模式；空壳补全后自动复活入 staging 验证门
- 举一反三：23 条死亡 staging 归档（audit_staging），staging_queue 26→3
- 去伪存真：evidence_filter 不再写假 pass；429 条存量假证据标记 skip（audit_evidence）
- health：熵=不稳定率真实计算；无数据指标显式 [N/A]（不再伪满分）
- 一二不过三：修复 post_tool 条件倒挂（原 `-notmatch '"error"'` 导致检测到错误反而跳过记录）
- 可观测性：PACE / PHASE_LOCK 落盘审计日志

- 引擎自检 13 项全绿（含 no_hollow_patterns / no_stale_staging / no_fake_evidence）
