迭进由八条元原则构成**互联网络**。每条原则不是孤立的步骤，而是网络中的一个节点——有自己的职责、触发时机、闭环出口，并通过**裁决律**与**去伪存真**与其他节点互联。



---



### 0. 裁决律（优先级宪法）



> **真伪至上 → 生存优先 → 完形封存**



当各原则发出冲突指令时，以下为硬编码的最高裁决逻辑，不可逾越：



| 优先级 | 规则 | 说明 |

|:-----:|:----|:------|

| P0 | 去伪存真无条件优先 | 验证为假的信息不进入任何原则的处理流程 |

| P1 | 一二不过三的阻断指令优先于攻七和举一反三 | 安全阀高于强化和泛化 |

| P2 | 止观门的"事毕清零"优先于守三的延伸纠错 | 完成后不追加纠错 |

| P3 | 缓急律的"紧急分流"优先于守三深度复盘 | 紧急时不启动深度反省 |

| P4 | 守三的改进规则与攻七的成功模式冲突时 → 置信度裁决 | 分别计算置信度（含 P6 语义记忆权重），高者胜出；delta≤0.1 视为无实质冲突，守三负向纠错优先 |

| P5 | 举一反三的staging规则不参与实时仲裁 | staging规则需先经过去伪存真验证才能激活 |
| P6 | Mindol 语义记忆权重（实现超集，补充定义） | 高分历史经验双向调节规则/模式置信度，仅影响 P4 与兜底，不凌驾 P0-P3 |



**裁决律不产生规则，只提供优先级排序。所有原则的输出最终汇聚到仲裁器，按上表裁决。**

> **P6 语义记忆权重（v3.8 实现补充）**
> 仲裁器在 P4 置信度裁决前，检索 Mindol 语义记忆（rule/pattern/codex/trade 空间，score≥0.8）：
> - 高分历史阻断/失败案例 → 相关拦截规则置信度 +0.5（支持拦截），相关成功模式 -0.3（削弱放行）
> - 高分历史放行/成功案例 → 相关拦截规则置信度 -0.3（削弱拦截），相关成功模式 +0.5（支持放行）
> - 权重仅作用于本次仲裁、不持久化；只调节 P4 与严重度兜底，绝不凌驾 P0-P3。

### 1. 守三（负向纠错）



> **拆解自己 → 找出不足 → 对比提炼 → 总结改进 → 写入固化 → 触发执行**



| 维度 | 定义 |

|:----|:-----|

| 步骤 | ①收集strike和失败数据 → ②拆解问题模式 → ③对比期望行为 → ④总结根因 → ⑤生成改进规则 → ⑥写入规则库→触发下一轮 |

| 时机 | **轻量自检**：每次操作前，扫描最近一次失败模式<br>**深度复盘**：每日/每N次操作后，系统性回顾strike日志 |

| 闭环 | 写入固化 → 触发执行 → 进入下一轮 |

| 互联 | ← 从一二不过三接收strike数据作为复盘素材<br>→ 向仲裁器输出改进规则<br>→ 向举一反三输出新规则作为泛化素材 |

| 约束 | 与攻七行动期严格隔离（守三运行时攻七不运行） |



---



### 2. 攻七（正向强化）



> **识别优势 → 复盘成功 → 提炼模式 → 主动写入 → 验证效果 → 迭代微调**



| 维度 | 定义 |

|:----|:-----|

| 步骤 | ①检测成功操作 → ②复盘成功原因 → ③提炼可复用模式 → ④写入success_patterns → ⑤去伪存真验证效果 → ⑥有效则固化，无效则迭代或淘汰 |

| 时机 | 成功案例发生后立即触发 |

| 闭环 | 验证通过 → 固化 → 进入下一轮；验证失败 → 回退到"识别优势"或淘汰 |

| 互联 | → 向举一反三输出成功模式作为泛化素材<br>→ 验证环节调用去伪存真<br>→ 与守三共享规则库，通过仲裁器解决冲突 |

| 约束 | 与守三深度复盘时间隔离 |



---



### 3. 一二不过三（三错锁）



> **①错立改+改毕验 → ②再错加固阻断 → ③三错升级处理**



| 维度 | 定义 |

|:----|:-----|

| 步骤 | ①检测错误 → 立即自动修复（立改）→ 验证修复结果（改毕验）→ 修复成功则向攻七输出成功模式<br>②同类错误再次出现 → 去伪存真归因过滤 → 内生惯性则写入硬阻断（dgen_override），外生变量则调整策略<br>③阻断仍出现第3次 → 推翻原阻断方案，通知用户，系统升级 |

| 时机 | 同类错误发生时实时触发 |

| 闭环 | 修复成功 → 输出到攻七 → 进入下一轮；阻断成功 → 仲裁器裁决；阻断失效 → 升级处理 |

| 互联 | → 修复成功的模式输出到攻七成为成功模式<br>→ strike数据输出到守三作为复盘素材<br>→ 阻断规则输出到仲裁器<br>→ 归因过滤调用去伪存真 |

| 约束 | 同一错误类型在第1次和第2次之间，系统保持警觉但不影响正常操作 |



---



### 4. 举一反三（跨域泛化）



> **举一 → 反三 → 通百 → 回归校验**



| 维度 | 定义 |

|:----|:-----|

| 步骤 | ①从单条规则/模式出发 → ②推导至少三种跨场景候选规则 → ③写入staging等待验证 → ④去伪存真执行回归校验 → ⑤有效≥2次则固化为活跃规则，否则放弃并记录边界 |

| 时机 | 新规则入库时 + 定期的批处理窗口 |

| 闭环 | staging → 回归校验 → 有效则固化/无效则放弃并记录 |

| 互联 | ← 从守三接收改进规则、从攻七接收成功模式作为泛化素材<br>→ 调用去伪存真执行回归校验<br>→ 泛化失败的边界记录反馈给守三 |

| 约束 | staging规则不参与实时仲裁，需验证后才能激活 |



---



### 5. 去伪存真（真伪门）



> **言必有证 → 证必可验 → 验证为真**



| 维度 | 定义 |

|:----|:-----|

| 步骤 | ①接收验证请求（含待验证的信息/规则/模式）→ ②检查证据来源和可靠性 → ③执行验证（逻辑校验/执行验证/历史对比）→ ④输出验证结论（真/假/暂存） |

| 时机 | **被动**：被其他原则调用时（攻七验证、一二不过三归因、举一反三回归校验）<br>**主动**：每次决策前验证输入信息的真实性 |

| 闭环 | 验证为真 → 允许进入下一环节；验证为假 → 拒绝+记录误判来源；无法判断 → 暂存区，标记"待验证" |

| 互联 | ← 被所有其他原则调用作为验证者<br>→ 验证结论输出到仲裁器<br>→ 误判记录反馈给守三 |

| 约束 | 对创新性假设可给予"暂存区"标签，允许极小成本试点，但试点后必须回归校验 |



---



### 6. 缓急律（节奏门）



> **急务求效 → 缓务求真 → 张弛有度**



| 维度 | 定义 |

|:----|:-----|

| 步骤 | ①判断任务类型（紧急/重要/常规/新信息）→ ②紧急：走快速通道（跳过守三深度复盘、举一反三、止观门完整流程）→ ③常规：走完整流程 → ④定时设置"宕机时段" |

| 时机 | 每次入口（最先执行） |

| 闭环 | 分流后进入对应执行通道 → 完成后回到缓急律判断下一任务 |

| 互联 | → 紧急通道调守三轻量自检后直接执行<br>→ 常规通道触发完整原则网络<br>→ 与止观门配合设置宕机时段 |

| 约束 | 紧急时"先事后人"——先完成交付，事后再复盘 |



---



### 7. 止观门（完形律）



> **事毕则封存 → 投入即清零 → 不恋战，不内耗**



| 维度 | 定义 |

|:----|:-----|

| 步骤 | ①检测任务完成或主动放弃 → ②打包关键经验与教训 → ③从工作内存中卸载 → ④归档到长期记忆 → ⑤不再进行守三的追加纠错或举一反三的后续衍生 |

| 时机 | 每轮结束时 + 缓急律的"弛"阶段定时触发 |

| 闭环 | 封存 → 清零 → 进入下一轮或等待 |

| 互联 | ← 接收所有原则的"完成"信号<br>→ 通知仲裁器当前轮次已封存<br>→ 与缓急律配合设置宕机时段 |

| 约束 | 封存后的事项不再追加纠错或强化，除非同一事项在新的上下文中重新出现 |
