# 迭进 vs LOOP vs 目标模式：AI 自我进化的三层，别只盯着一个

> 当「让 AI 自己变得更好」成为刚需，三种范式常常被混为一谈。这篇文章把它们拆开。

## 先说清一件事：这三样不是竞品，是三个不同楼层

「AI 会自我进化」是 2026 年最热的话术之一。但你去问三拨人，得到三个答案：

- 用 **LOOP / Reflexion** 的人说：进化就是「做→反思→重做」，多循环几轮就行；
- 用 **Codex 目标模式**的人说：进化就是「设个目标让它自己跑」，跑完续跑；
- 做 **记忆框架**的人说：进化就是「让它记住」，检索得到就进化了。

三拨人说的都对，但**说的是三件不同的事**。这篇文章把它们拆开——不是要分高下，而是告诉你：**你缺的到底是哪一层，以及为什么大多数人只用了前两层，却以为自己已经拥有了第三层。**

---

## 一、先给结论

> **目标模式 = 导航（要去哪）；LOOP = 驾驶动作（怎么开）；迭进 = 车载进化系统（越开越稳、越开越聪明、错不重犯）。**

三者不冲突，可以叠加运行。但如果你要的是「AI 长期越来越好」，只有第三层是答案。

## 二、三种范式逐一看

### 2.1 LOOP 类循环模式（Reflexion 等）

**本质**：单轮「执行 → 反馈 → 反思 → 再执行」的循环模板。

解决的是「**这一次**怎么做好」。

2026 年这个赛道还在快速演进：

- **Reflexion 已从「做 → 反思 → 重做」升级为 `plan → reason → act → reflect` 的层叠循环**（2026-06），把「规划」也纳入反思闭环，在 HumanEval 上做到 91% pass@1；
- **LangGraph 2.0 于 2026-02 发布**，把这类循环变成可编排、可持久化的图结构，成为不少 Agent 团队的标配编排层；
- Mem0 等记忆框架也在补齐「时间推理」与「记忆衰减」，让循环内可召回的经验更贴近时点。

但演进没有改变 LOOP 的天花板——它依然是一个**单轮内的战术循环**：

| 维度 | LOOP 类循环 |
|:--|:--|
| 记忆 | 依赖对话上下文/外部向量库，循环结束即散 |
| 纠错 | 反思后重试（同一层面反复） |
| 强化 | 弱——只反思失败，很少固化成功 |
| 仲裁 | 无/隐式 |
| 调度 | 无 |
| 依赖 | 常需 LLM API / 外部服务 |
| 层次 | 方法/模板（战术） |

**一句话**：LOOP 是驾驶动作——教 AI「这一把怎么开」。

### 2.2 Codex 目标模式（goals）

**本质**：平台级任务管理（目标/预算/延续/续跑）。

解决的是「**任务怎么推进**」。2026 年它已正式转正：

- `/goal` 于 2026-04 上线，**2026-05-21 正式 GA（Codex CLI 0.133.0）**，支持长时间无人值守任务；
- 目标模式把长任务的「断点续跑」做成平台能力，是导航层最成熟的落地形态之一。

| 维度 | 目标模式 |
|:--|:--|
| 作用面 | 单线程任务的推进与续跑 |
| 失败处理 | 任务中断/超时由平台控制 |
| 成功沉淀 | 不沉淀 |
| 记忆 | 无（任务级） |
| 层次 | 任务管理（运营层） |

**一句话**：目标模式是导航——告诉 AI「要去哪、还剩多少油」。

### 2.3 迭进（Diegin / DGEN）

**本质**：AI 操作系统级进化层——律令九章（四律三门一锁一镜）原则网络 + 引擎 + 语义记忆 + 平台钩子。

解决的是「**AI 长期怎么越来越好**」。截至 2026-08-25 的实测快照：

**拦截与净化：280 条规则**（81 条活跃 + 188 条归档）——每一条都经过守三审核与去伪存真过滤后入库；死规则 0、空壳模式 0、伪证据 0。

**记忆有生命周期：9,814 条记忆单元**（动态增长）——权威记忆（规则/模式/交易/用户）永久保留，工具中间日志按 1/3/7 天分档休眠，每日自动维护，只留有用的。

| 维度 | 迭进 |
|:--|:--|
| 记忆 | Mindol 语义记忆持久化，跨会话长期沉淀 + 生命周期治理 |
| 纠错 | 守三拦截 + 一二不过三升级（阻断→固化→通知用户） |
| 强化 | 攻七成功模式提炼（47 个模式，45 个自动采纳）+ 举一反三泛化 + 去伪存真验证 |
| 仲裁 | 预策·裁决律显式仲裁（P0-P6 硬优先级） |
| 调度 | 预策统摄 + 止观·完形律封存 + 恒常门续接（473 个任务快照可跨会话恢复） |
| 依赖 | 纯本地、零外部 API，numpy 即可 |
| 层次 | 操作系统级进化层（战略） |

**一句话**：迭进是车载进化系统——越开越稳、越开越聪明。

## 三、关键差异对照表

| 维度 | LOOP 循环 | 目标模式 | 迭进 |
|:--|:--|:--|:--|
| 本质 | 循环模板 | 任务管理 | 进化层 |
| 时间尺度 | 单轮 | 单任务 | 长期（跨会话） |
| 错误处理 | 反思重试 | 平台中断 | 立改→阻断→升级 |
| 成功沉淀 | ✗ | ✗ | ✅（攻七+泛化） |
| 记忆 | 循环内 | 无 | 语义记忆（跨会话） |
| 冲突仲裁 | ✗ | 平台规则 | 预策·裁决律 P0-P6 |
| 状态 | 无 | 任务级 | 常驻（钩子+规则库） |
| 断点续接 | ✗ | 平台续跑 | 恒常门跨对话恢复（任务级快照） |

## 四、可以叠加：三层一起用

迭进不排斥前两者，反而可以**容纳**它们：

- 在 **Codex 目标模式**会话里，迭进钩子全程常驻：工具调用前预检、回复前纠错、成功时沉淀模式——目标模式是迭进的「任务载体」之一（引擎模式库中已存在与目标模式联动的自动沉淀记录）；
- LOOP 循环可以成为迭进执行循环中的一种战术：迭进负责「进化」，LOOP 负责「本轮执行」。

## 五、实证：迭进在真实会话中的表现

- **攻七成功模式已与目标模式联动**：引擎成功模式库中存在 `pat_auto_tool_create_goal_1` / `pat_auto_tool_update_goal_1` / `pat_auto_tool_get_goal_1`，证明迭进真实运行在目标模式会话中并沉淀成功经验；
- **举一反三 ×2 当日 71/74 次命中、零误伤**（2026-08-10）：跨域泛化规则入库次日实战大量触发，人工复核无误伤后保留；
- **攻七闭环 24 小时跑通**：规则「入库 → 实战 → 自动采纳（置信度 +0.5）」一天内完成；
- **恒常门跨对话恢复破冰（2026-08-18）**：恢复率从 0 完成首次实证——「恢复 A股模拟盘那个任务」意图匹配唯一高置信命中（0.760，领先次名 0.286）并自动恢复；目前恒常门共 473 个任务快照（392 暂停 / 69 完成 / 8 放弃 / 4 阻塞）可跨会话续接；
- **质量闸门持续全绿**：引擎自检 16/16、端到端测试 33/33，死规则/空壳模式/伪证据长期为 0——它不「声称」有效，而是「验证」有效。

## 六、怎么选

| 你的需求 | 推荐 |
|:--|:--|
| 本轮任务做得好一点 | LOOP / 更好的 Prompt |
| 长任务推进与续跑 | 目标模式 |
| 团队长期积累「AI 怎么用才对」 | 迭进（或三件套叠加） |

## 结尾

「AI 会自我进化」不该只是口号。LOOP 让它单轮更稳，目标模式让它跑得更远，迭进让它**记得住、不再犯、越用越聪明**。
