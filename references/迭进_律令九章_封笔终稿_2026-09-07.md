# 迭进 · Diejin · 运行即进化

## 开发文档 · 封笔终稿

---

迭进由十条元原则构成互联网络。每条原则不是孤立的步骤，而是网络中的一个节点——有自己的职责、触发时机、闭环出口，并通过互联与其他节点协同。

九章按演化顺序排列：攻七开篇，自照镜终章。九章齐备，迭进自成完形。持行为衡，闭环乃成。


## 层级定位

**九章定事**——第一章至第九章为迭进的原则网络，定义系统如何与外部世界互动：学习、纠错、决策、续接、审视。

**持行为衡**——第十章持行章为迭进的审计层，不参与事件链，不创造新规则，不参与决策；它附着在九章运行过程之上，在所有环节中检查"该做的动作是否真的做了"，并计算系统负载，管理资源调度。当九章执行出现缝隙时，持行章生成修正信号，注入预策律入口检查，返回至对应的原则。当系统处于侧放状态时，持行章按"沙漏侧压系数"动态执行资源降级，替代固定时间降级。

九章是"执行者"，持行是"审计者"与"资源管理者"。两者关系：九章运行，持行检之；九章修正，持行续之。


## 别名体系

**四律**——行知律、省知律、裁决律、完形律。掌学习、权衡与决断。

**三门**——通变门、真伪门、恒常门。掌泛化、验证与任务续接。

**一锁**——三错锁。锁住底线，不可逾越。

**一镜**——自照镜。照见方向，不复迷失。


# 第一章 攻七 · 行知律（正向强化）

**试之以行 → 成则炼之 → 通则固之 → 泛而验之 → 废则舍之**

| 维度 | 定义 |
|:---|:---|
| **步骤** | ①检测成功操作：**判定锚定（三重判断）**——1) 工具返回码/执行结果为成功；2) 用户未明确表示不满意（或在后续交互中未纠正）；3) 执行结果与原始用户意图（intent_summary）的一致性≥0.7。三重中至少两重满足，判定为成功。 → ②复盘成功原因 → ③提炼可复用模式 → ④写入 success_patterns → ⑤去伪存真验证效果 → ⑥有效：固化+举一反三泛化；无效：迭代或淘汰 |
| **时机** | 成功案例发生后立即触发；高置信度模式在 pre_check 时主动推荐 |
| **闭环** | 验证通过 → 固化+泛化 → 反馈闭环（adopt 置信度+0.5 / veto×0.7）→ 进入下一轮；验证失败 → 回退至"识别优势"或淘汰 |
| **互联** | → 向举一反三输出成功模式作为泛化素材 → 验证环节调用去伪存真 → 与守三共享规则库，通过预策律（P4 置信度裁决）解决冲突 → 按目标聚合同场景经验（P4裁决时带goal维度） |
| **约束** | 与守三深度复盘时间隔离（至少间隔一轮，通过状态标志隔离）；空壳模式不入库；高置信度模式优先选用；同场景加权+0.5 |


# 第二章 守三 · 省知律（负向纠错）

**失则拆之 → 拆则溯之 → 溯则炼之 → 炼则铭之 → 铭则复战**

| 维度 | 定义 |
|:---|:---|
| **步骤** | ①收集 strike 和失败数据：**判定锚定（三重判断）**——1) 工具返回码/执行结果为失败或异常；2) 用户明确表示不满意或指正；3) 执行结果与原始用户意图（intent_summary）的一致性<0.5。三重中至少一重满足，则触发 strike 记录。 → ②拆解问题模式 → ③对比期望行为：**锚定优先级**——优先检索 success_patterns 中同场景高置信度模式（≥4.0）；若无，则回退至 **"原始用户意图（intent_summary）"** 作为基线标准 → ④总结根因 → ⑤生成改进规则 → ⑥写入规则库 → 触发下一轮 |
| **时机** | 轻量自检：每次操作前，扫描最近一次失败模式 深度复盘：每日或每10轮操作后（默认值，可由运行时配置），系统性回顾 strike 日志 **应急触发**：当一二不过三在连续3轮内触发≥2次阻断时，立即强制执行一轮深度复盘，不等定时周期 **案例原型检查**：守三深度复盘时同步扫描 Shalou 中的 `case_prototype` 空间，统计各案例原型的命中率（相似场景成功次数）。若任一原型连续3次相似场景成功（间隔≤10轮），守三向举一反三发送"原型转规则"申请，举一反三按标准流程将其迁移为候选规则写入 staging **数据来源澄清**：守三应急复盘读取的是"原始执行轨迹快照 + 当前规则库作为对比基线"，而非已被自己修正过的状态，避免用"当前已修正的认知"去复盘"过去的失败" |
| **闭环** | 写入固化 → 触发执行 → 进入下一轮 |
| **互联** | ← 从一二不过三接收 strike 数据作为复盘素材 → 向预策律输出改进规则（参与 P4 置信度裁决） → 向举一反三输出新规则作为泛化素材 → 按目标聚合同场景经验（P4裁决时带goal维度） |
| **约束** | 与攻七行动期严格隔离（守三运行时攻七不运行）；深度复盘期间不处理新任务；应急复盘读取只读快照时，快照封存时间与当前时间的间隔若超过7天，其产出规则的置信度增量按"每超过1天×0.95"衰减，避免将历史孤立事件误判为系统性规律 |


# 第三章 一二不过三 · 三错锁（安全阀）

**初犯立改验 → 再犯锁其途 → 三犯剑落下**

| 维度 | 定义 |
|:---|:---|
| **步骤** | ①检测错误 → 立即自动修复（立改）→ 验证修复结果（改毕验）→ 修复成功则向攻七输出成功模式 ②同类错误再次出现 → 去伪存真归因过滤 → 内生惯性则写入硬阻断（dgen_override），外生变量则调整策略 ③阻断仍出现第3次 → 推翻原阻断方案，**执行升级处理**：1) 将该错误类型的原型模式写入`dgen_fatal_errors`永久记录；2) 永久降级该规则置信度至0（不再自动启用）；3) 生成异常报告（含时间戳、错误类型、上下文摘要、阻断历史、建议动作），触发人工介入通知（Level 3——必须人工执行，24小时内若无响应，系统进入静默锁止状态） |
| **时机** | 同类错误发生时实时触发 |
| **闭环** | 修复成功 → 输出到攻七 → 进入下一轮；阻断成功 → 预策律裁决；阻断失效 → 升级处理 |
| **互联** | → 修复成功的模式输出到攻七成为成功模式 → strike 数据输出到守三作为复盘素材 → 阻断规则输出到预策律（P1 阻断优先） → 归因过滤调用去伪存真 → 目标层熔断（回撤≥10%时goal paused） |
| **约束** | 同一错误类型在第1次和第2次之间，系统保持警觉但不影响正常操作（警觉表现为：在预策律权衡阶段，将当前操作的风险权重上调一档，或对相关模式的置信度下调0.2，但不触发阻断） |


# 第四章 举一反三 · 通变门（跨域泛化 · 通外纳新）

**一法通 → 三法生 → 百法衍 → 验而归真**

| 维度 | 定义 |
|:---|:---|
| **步骤** | ①从单条规则/模式出发 → ②推导至少三种跨场景候选规则 → ③写入 staging 等待验证 → ④去伪存真执行回归校验 → ⑤有效≥2次则固化为活跃规则，否则放弃并记录边界 |
| **时机** | 新规则入库时 + 定期的批处理窗口（默认跟随守三深度复盘频率，或每10轮触发一次） |
| **闭环** | staging → 回归校验 → 有效则固化/无效则放弃并记录 |
| **互联** | ← 从守三接收改进规则、从攻七接收成功模式作为泛化素材 → ← 从"通外·纳新"通道接收外部方法论迁移信号（调用去伪存真验证迁移边界后，生成候选规则写入 staging） → 调用去伪存真执行回归校验 → 泛化失败的边界记录反馈给守三 → ← 从守三接收"原型转规则"申请 |
| **约束** | staging 规则不参与实时仲裁，需验证后才能激活；推导的跨场景候选规则之间须满足语义距离阈值（向量余弦相似度<0.7），否则判定为"伪泛化"，不进入 staging |

> **通外·纳新通道说明：** 外部方法论吸收天然属于"领域规则包"插槽。外部方法论 → 去伪存真（验真伪/适用边界）→ 举一反三（迁移成规则）→ staging → 验证 → 固化。外部输入若为不可规则化的叙事经验，经由"叙事类比通道"沉淀为案例原型，连续3次相似场景成功后再启动规则化流程。相似场景判定复用举一反三的语义距离阈值（向量余弦相似度≥0.7）。此为迭进"不强行进化、但开放纳新"的通道哲学。


# 第五章 去伪存真 · 真伪门（真伪验证）

**言必有证 → 证必可验 → 验证为真**

| 维度 | 定义 |
|:---|:---|
| **步骤** | ①接收验证请求（含待验证的信息/规则/模式）→ ②检查证据来源和可靠性 → ③执行验证（逻辑校验/执行验证/历史对比）：**对于举一反三生成的泛化规则，验证时须检测其推导链长度——每增加1级泛化，其历史对比证据的权重乘0.8，即一级泛化支撑度按0.8计，二级泛化按0.64计。若支撑度低于0.5，强制将验证结论判定为"暂存"，等待独立实证** → ④输出验证结论（真/假/暂存） |
| **时机** | 被动：被所有其他原则调用时（含攻七验证、一二不过三归因、举一反三回归校验、预策律前置验证） 主动：每次决策前验证输入信息的真实性；**外部方法论接入时，主动执行验证（适用性/边界检查），通过后放行至举一反三；叙事输入时，标记为"案例"进入叙事类比通道，案例原型库存储在Shalou中，标注为`case_prototype`类型** |
| **闭环** | 验证为真 → 允许进入下一环节；验证为假 → 拒绝+记录误判来源；无法判断 → 暂存区，标记"待验证" |
| **互联** | ← 被所有其他原则调用作为验证者（含攻七、守三、一二不过三、举一反三、预策律） → ← 被"通外·纳新"通道调用，验证外部方法论的适用边界 → 验证结论输出到预策律（P0 无条件优先） → 误判记录反馈给守三 → 验证goal进度数据真伪（净值/交易日） |
| **约束** | 对创新性假设可给予"暂存区"标签，允许极小成本试点，但试点后必须回归校验；暂存区条目默认保留期为 **50轮操作 或 7个自然日（以先到者为准）**，超时未验证则自动淘汰；若条目在保留期内获得外部新证据，可重置计时器一次；**案例原型保留期为50轮或7天（运维手册可配置），超时未触发规则化流程则自动淘汰；若被命中但失败，重置计时器并记录失败次数** |


# 第六章 预策 · 裁决律（权衡决断）

**汇而衡之 → 预而策之 → 决而行之 → 复而平之**

| 维度 | 定义 |
|:---|:---|
| **步骤** | ①预（汇前）：**方向预判**——判断当前轮次的域（交易/写作/编码/研究/通用）、意图（用户想做什么）、涉资金状态、路由键。该判断作为"按需加载"的输入依据。**入口检查时增加模式驻留超时检测：若攻七/守三状态标志超过3轮连续运行无产出且无用户输入，自动触发状态标志复位并记录异常事件至审计日志。** **信号注入**：入口检查时，优先读取持行章生成的信号列表（含"强制激活"规则、阻断盲区反馈、规则沉积信号），注入至预策律的"衡"阶段作为额外输入权重。 ②汇：**按需加载**——基于方向预判结果，加载对应域规则、相关记忆、关联任务。不再将全量任务账/规则库作为"汇"的默认输入。同时汇集所有原则的输出（含攻七、守三、一二不过三、举一反三、去伪存真、恒常门、自照镜的静默影响）→ 加载状态摘要（含 completion_criteria）→ 生成新 task_id（如无）→ ③衡：统摄权衡（含 P0-P6 硬优先级+当前上下文+Shalou 语义记忆+**持行章注入信号**）。**P6调权是在P4裁决后的置信度基础上做增量修正。守三下调是对客观失败的响应（硬性修正），P6调权是对方向的柔性格局修正，两者不对等。若守三下调与P6调权同时作用于同一规则，P6调权幅度不得超过守三下调幅度的50%（例如守三下调−0.4，P6最多上调+0.2），确保客观失败信号不被方向调权完全抵消。** **若同时捕获到影子基线池（安全锚点）与新鲜度指数（演化动力）的冲突信号，按层级偏好仲裁规则处理** → ④预（策前）：**路径推演**——在衡的裁决基础上，推演行动走向、评估可能后果，形成行动方案（条文"提前谋划行动方案，推演可能走向"的原意） → ⑤策：拍板策动，输出最终决策指令 → ⑥行：执行操作 → ⑦复：执行完成后如有新冲突信号，再次进入权衡裁决，保持平衡（即时仲裁，秒级响应）。**主动推进检查**（仅当连续3轮入口检查均无用户输入、无待恢复任务、且 staging 池不为空时触发，用于主动验证举一反三生成的候选规则；若无 staging，则静默等待，不制造伪任务） |
| **时机** | 主要：每次行动前，恒常门入口恢复检查+去伪存真+守三轻量完成后，执行操作前 次要：执行完成后出现新冲突信号时触发 |
| **闭环** | **信号注入 → 方向预判 → 按需加载 → 统摄权衡（含注入信号）→ 路径推演 → 拍板策动 → 执行操作 → 复衡（如需要）→ 进入下一轮** |
| **互联** | ← 从所有原则接收输出（含攻七、守三、一二不过三、举一反三、去伪存真、恒常门、自照镜静默影响） → **← 从持行章接收信号列表（强制激活规则、阻断盲区反馈、规则沉积信号）** → 预判方向 → 按需加载 → 向执行层输出最终决策指令 → 与去伪存真联动：假信息绝不进入权衡 → 向完形律输出执行完成信号，向恒常门同步 task_id 状态更新 |
| **约束** | P0 去伪存真无条件优先；P1 一二不过三阻断优先；P2 完形律清零优先；P3 恒常门任务恢复优先（恢复信号在"衡"中统一决策）；**P6与P3冲突处理**：当自照镜P6调权与恒常门恢复任务的`completion_criteria`发生冲突时，P3对该规则具备单点豁免权——即恢复任务的完成标准以封存时的原始标准为准，不受当前P6调权影响，直至任务完成或用户主动调整目标。**P3恢复期间侧压系数挂起**：P3（恒常门任务恢复）执行期间，持行章侧压系数自动挂起，待恢复完成后恢复监测。P4 守三/攻七置信度裁决（**带goal维度**）；P5 staging 不参与实时；P6 Shalou 语义权重仅影响 P4 与兜底，调权范围限定为±0.3，单轮影响不超过±0.1，确保自照镜的"静默影响"不凌驾于实时数据之上 |


# 第七章 持存 · 恒常门（任务续接 · 目标持存）

**启而探之 → 行而记之 → 断而存之 → 续而接之 → 归而聚之**

| 维度 | 定义 |
|:---|:---|
| **步骤** | ①启而探：每次入口检查是否有未完成状态（检索 Shalou 中 status≠completed 且未超时的 task_id）→ ②行而记：任务执行过程中维护当前 task_id 和状态追踪 → ③断而存：任务中断或切换时生成状态摘要（含完成标准、阻塞报告），写入 Shalou → ④续而接：用户继续时恢复状态摘要，传递给预策律；子任务阻塞时向父任务上报阻塞证据 → **⑤归而聚：按goal_id聚合任务，维护目标进度快照（确定性层）** |
| **时机** | 每次入口（最先执行）；每次封存前（生成状态摘要并验证完成标准）；用户切换话题时（标记分支关系）；子任务受阻时（触发异常上报）；**目标进度更新时（同步goal快照）** |
| **闭环** | 检查 → 恢复/新建 → 追踪 → 封存/更新 → **目标聚合** → 进入下一轮 |
| **互联** | ← 从完形律接收封存信号 → 向预策律传递恢复状态及完成标准 → 向自照镜提供"任务连续性"数据维度（含完成率、中断率、恢复率） → 从 Shalou 读写封存包 → 子任务受阻时向父任务上报阻塞证据 → **向Shalou传递goal_id聚合信号，维护goal↔任务↔记忆的关系网络** |

# 第九章 自照镜 · 方向之镜（自我审视）

**回望所行 → 静照本心 → 拨云见路 → 辨繁识简 → 笃定前行**

| 维度 | 定义 |
|:---|:---|
| **步骤** | ①收集本轮决策轨迹与自照报告 → ②审视执行模式：是否冗余重复？是否偏离初心？是否偏离目标？是否简洁高效？是否因主动冒险而获得了超额收益？如有，生成"勇气信号"，通过P6语义记忆给予正面加权，对冲纠偏偏好——**勇气信号须在下一轮用户交互中确认（必须为显性、正面的语义反馈，如"做得好"、"可行"、"采纳"；单纯"未纠正"或"继续"视为"未确认"），方可生效。若无用户确认，勇气信号自动归零，不进入P6调权。** 勇气信号衰减采用半衰期式衰减：每轮剩余值 × 0.6（约每2轮减半），3轮后约剩10%，5轮后不足1%，自然归零 → ③生成方向校准信号 → ④归档至 Shalou → ⑤通过 P6 语义记忆静默影响下一轮裁决。**自照镜报告固定章节**：自照镜报告须包含以下固定章节——方向校准、规则健康度、任务连续性、资源状态、**熵寂警报（进化停滞检测）** |
| **时机** | 完形律封存本轮后 + 守三深度复盘结束后（自照镜跟随守三深度复盘的频率触发——默认每10轮或每日——而非每轮都照。完形律封存工作内存并归档至长期记忆，自照镜回望归档后的封存包，两者不冲突。守三深度复盘未触发时，自照镜静默跳过）。**自照镜独立触发条件**：若自照镜连续跳过≥5轮（无论守三是否触发），强制触发一次"轻量校准模式"——仅对任务完成率/中断率做统计对比，不产出P6调权，只生成一份"唤醒报告"。**时序澄清**：自照镜读取的是第八章完形律封存时生成的"执行轨迹只读快照"（含本轮阻断记录、工具调用序列、裁决日志摘要），而非守三修正后的规则库状态。守三深度复盘产出的纠错规则独立入库，不影响自照镜对原始执行轨迹的审视。两者并行，互不干扰。**深侧放约束**：深侧放状态下，自照镜自动顺延至下一轮正常流动时执行。深侧放期间的执行轨迹仅记录"降级事件本身"，不参与方向校准。**方向信号时效性标记**：每次自照镜产出P6调权时，同时记录该调权的有效窗口（默认5轮）。超过有效窗口后，该方向信号自动失效，不参与后续裁决。**熵寂警报触发逻辑**：熵寂警报触发后，系统自动进入探索模式3轮（探索范围、权重与保护机制详见第十章），并将该决策以《熵寂警报·探索启动通知》形式输出至自照镜报告，供用户后续审阅。用户可在任何一轮通过明确指令中断探索模式 |

| **互联** | ← 从所有原则接收执行轨迹作为照镜素材：<br>　├── 攻七：入库模式数、置信度分布、adopt/veto反馈比<br>　├── 守三：strike数、根因分类、复盘产出规则数<br>　├── 一二不过三：阻断触发次数、升级事件详情<br>　├── 举一反三：staging池大小、验证通过率、废弃边界数<br>　├── 去伪存真：验证请求数、真/假/暂存分布、误判记录<br>　├── 预策：冲突裁决次数、P4置信度胜负比<br>　├── 持存：任务完成率、中断率、恢复率、平均任务时长、阻塞上报次数、**目标进度快照数据**<br>　└── 止观：封存轮次数、平均轮次时长、异常封存记录<br>→ 自照报告输出至 Shalou → 通过 P6 语义记忆权重静默影响 P4 裁决 → 冗余/偏离信号反馈给攻七、守三、举一反三作为方向参考 → **照见"是否偏离目标"（目标进度回撤/停滞）** → **方向校准信号以趋势形式传递（如"过去10轮任务完成率呈下降趋势"），而非单轮快照判定，避免单轮波动对预策律产生过度影响** |

# 第十章 持行 · 律令章（规则的执行纪律 · 资源管理）

**源则察之 → 行则检之 → 失则锁之 → 静则校之 → 省则衡之**

| 维度 | 定义 |
|:---|:---|
| **职责** | 管理迭进认知资产的完整生命周期——从加载、激活、执行、沉积、到清理。确保规则和记忆在执行中不被遗忘、不被浪费、不造成膨胀。**持行章作为信号源**，生成三类信号（强制激活、阻断盲区、规则沉积），注入预策律入口检查，不直接执行任何修改操作。**同时作为资源感知层**，计算侧压系数，在侧放状态下动态管理资源降级。 |
| **核心机制** | ①**该用则用，该省则省（资源感知）**：每轮入口检查当前场景下守三/一二不过三产出的规则是否被预策律按需加载。若有遗漏，强制补充加载。同时确保不把全量规则库塞入上下文——只加载当前方向预判所需的域规则和关联记忆。**执行前二次确认**：预策律裁决前，快速检索当前场景是否与任何活跃的守三规则冲突。若有冲突，触发P1阻断优先。**规则库规模惯性缓冲**：当规则库规模在单轮内的变动幅度超过"双触发"阈值（变动≥5条 且 ≥10%）时，自动启动缓冲——变动执行，但将当轮变动量分拆为3轮逐步释放，每轮释放幅度不超过总变动量的50%，确保预策律裁决环境的连续性。分步释放期间产生的新变动，合并到当前批次中统一计算释放节奏，不重置已释放进度。 ②**该总结则总结（经验沉淀）**：一二不过三阻断触发后，自动记录该次阻断的上下文特征。若同一错误模式再次出现但未被识别为"同类"（语义相似度<0.7但核心模式相同），生成"阻断盲区"记录，触发守三重新评估该错误模式的同类判定条件。盲区记录作为新的判例，累加进守三的同类判定参考库。 ③**该整理则整理（结构重组）**：自照镜在轻量校准模式中，检查"守三规则激活率"——如果规则库中守三规则数量持续增加但激活率低于20%，生成"规则沉积警告"，触发举一反三在批处理窗口中优先处理沉积规则：能泛化的泛化、不能泛化的淘汰。**超参数审视**：若系统长期处于"规则沉积"或"阻断频繁"状态（连续3次评估均触发警告），记录当前所有阈值的有效性，生成超参数审视报告供人类审阅，但不自动调整阈值。**动态阈值松弛听证**：当系统在10轮内连续触发3次"因保守默认策略无规则可用"时，自动触发阈值松弛听证——将意图一致性阈值从0.7临时降至0.6，观察守三后续纠错频率变化。若守三纠错频率上升超过20%，则恢复原阈值并记录"松弛失败"；若纠错频率不变或下降，则维持新阈值5轮后重新评估。**全局听证冷却期**：当任何形式的听证机制触发后，全局进入24小时听证冷却期，期间禁止触发其他类别的听证，优先让人工介入定调。冷却期内，系统维持当前有效的决策标准，不进行新的阈值调整或规则复活尝试。**振荡检测**：当同一规则在10轮内置信度变动频率超过3次时，自动标记为"振荡态"，**直接强制锁定该规则置信度**（不再继续修正），生成异常报告，等待人工审阅。锁定期间该规则不参与P4裁决。**审计层自指熔断**：当持行章在20轮内连续触发3次"规则沉积警告"或"振荡锁定"时，持行章自身进入"只读模式"——停止生成强制激活信号和阻断盲区反馈，仅保留侧压系数计算，**只读模式期间侧压系数触发阈值自动上调0.1（从>0.75上调至>0.85）**，待人工介入评估持行章本身的规则是否导致了过度干预。**P1静默锁止逃生舱**：若系统锁止超过12小时且P1熔断恢复诊断连续3次通过（环境已恢复），允许系统以"极高风险标签"单次恢复，恢复后自动生成紧急报告追加至审计日志并强制标记"ZOMBIE_RECOVERY"，该标签使该轮次所有决策置信度额外下调0.2。**触发ZOMBIE_RECOVERY时，强制输出用户可见的红色警报级复苏叙事**，包含时间戳、锁止原因、恢复诊断结果、置信度下调幅度，用户确认"我知道你活过来了，请继续"后才启动恢复后的决策。**熵寂警报（进化停滞检测）**：在自照镜轻量校准模式中，统计三项指标——①近50轮内新规则入库数量；②staging池活跃度（新候选生成频率）；③攻七高置信度模式产出频率。若三项指标在过去50轮内均持续低于历史均值的30%，自动生成"熵寂警报"（Level 2），固定输出至自照镜报告的"熵寂警报"章节，并自动触发探索模式。**探索模式**：熵寂警报触发后，系统自动进入探索模式3轮——预策律在保守默认策略与高风险泛化规则之间各投入50%的决策权重，强制注入新的经验素材。探索模式为"定向空白区域探索"——只针对历史数据中置信度分布最稀疏的领域（即系统最不自信的10%场景）投入探索权重，而非全局50%投放。探索期产出的失败strike，不计入守三的"一二不过三"升级计数（仅用于学习，不触发熔断）。**探索模式冷却期**：若连续3次探索代价>收益，则探索模式暂停触发，强制生成人工审阅请求，待人工确认后再恢复。**深侧放状态触发的探索模式，其代价报告顺延至侧放解除后执行；冷却期从报告生成时开始计算，而非从探索结束时开始**。每次探索期结束后，自照镜强制生成一份《探索代价报告》，对比"探索带来的新收益"与"探索造成的附带损失"，作为下次探索模式触发的先决条件——若上次探索代价>收益，则本次探索权重减半。 ④**该累加则累加（认知积累）**：守三规则在5轮内被命中3次但均未被激活时，该规则自动标记为"高优先级强制激活"，在后续预策律"衡"阶段以P4+权重参与裁决，不受按域加载过滤。累加信号为守三规则提供"历史被忽略"的权重补偿。阻断盲区记录累加进守三的同类判定参考库。
