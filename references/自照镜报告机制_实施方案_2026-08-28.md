# 自照镜报告机制 · 第一批实施方案（L1 前置地基）

日期：2026-08-28
性质：**L1 前置地基（非 L1 九项本身）**。本批不改变任何裁决行为，只建立「自照镜报告对外可见面」与「P6 影响审计通道」，为 L1 九项（2.11/2.12/2.14/2.16）提供承载出口。
边界声明：本批落地后，L1 九项机制仍为「待人工确认」，未触碰引擎裁决逻辑。

## 一、现状（已核实）

- `engine/evo/self_mirror.py` 已有完整报告生成链路：
  - `generate_report()` 已收集九章素材：攻七/举一反三/止观/持存/一二不过三/预策/守三/去伪存真/自照镜 + `direction_calibration`
  - `mirror()` 执行自照 → 生成报告 → 归档 Shalou（self_mirror + direction_calibration 两空间）→ 同向熔断 → 更新轮次
  - `reports` 仅保留最近 10 条于 `var/state/self_mirror.json`
- 现状缺口：
  1. **无人类可读的独立报告文件**——报告仅存在于 state JSON 与 Shalou 空间，用户无法直接审阅完整自照报告（L1 各机制要求的「听证结果标注」「方向漂移警示」将挂在报告上）
  2. **无 P6 影响审计日志**——`arbiter._apply_memory_weight()` 做 P6 调权，但不记录来源/幅度/后续裁决（运维手册 2.4 明确要求）

## 二、目标

1. 每次自照镜运行后生成一份人类可读报告（Markdown + JSON 双份），落盘 `var/reports/self_mirror_<round>.md/.json`，并保留最近 30 份（对应手册快照全集 30 的运维习惯）
2. 建立 P6 影响审计日志 `var/logs/p6_audit.jsonl`（环形 1000 条，对应手册 2.4「90天/1000条以先到者为准」的记录上限；衰减/压缩规则属 2.7，仍待人工确认，本批只记录不清理）
3. 为 2.11/2.12/2.14/2.16 预留报告挂载点：报告模板含 `l1_pending` 区块（当前为空，后续机制逐项挂入）

## 三、组件设计

### 组件 A：自照镜报告文件（人类可读）
- 挂接点：`self_mirror.mirror()` 末尾，`self._save()` 之后
- 行为：把 `report`（已含九章素材 + direction_calibration + suppress 标记）序列化为：
  - `var/reports/self_mirror_r<round>.md`：表格化九章素材 + 方向校准信号 + 勇气信号 + 同向熔断/应急抑制标记 + L1 挂载点（空）
  - `var/reports/self_mirror_r<round>.json`：原始 dict
- 保留策略：仅保留最近 30 份（md+json 成对），更早删除（幂等，无副作用）
- 输出示例（md 结构）：
  ```
  # 自照镜报告 r13835 · 2026-08-28T08:52:03
  ## 九章素材
  | 原则 | 关键指标 |
  | 攻七 | 模式数 46 / 均信 4.95 / 最高 5.0 |
  | 举一反三 | staging 5 |
  | ...（止观/持存/一二不过三/预策/守三/去伪存真/自照镜） |
  ## 方向校准信号
  - （信号列表，无则「无」）
  ## 状态
  - 同向熔断静默: false | 应急抑制: false | 温启动: false
  ## L1 挂载点（待人工确认）
  - 2.11 真理跌落听证: （空）
  - 2.12 影子基线池漂移: （空）
  - 2.14 新鲜度指数: （空）
  - 2.16 宪法解释请求: （空）
  ```

### 组件 B：P6 影响审计日志
- 挂接点：`arbiter._apply_memory_weight()` 内部，每次对规则/模式应用 delta 后
- 记录字段（对齐手册 2.4：来源/幅度/后续裁决）：
  ```json
  {"ts":"...","round":N,"rule_id":"...","source":"shalou_hit:<uid>","delta":0.1,"direction":"up|down","decision_after":"block|allow|...","reason":"P6记忆"}
  ```
- 落盘：`var/logs/p6_audit.jsonl`（追加写，环形 1000 条：超限丢弃最旧）
- 权限：只读日志，不参与裁决；不自动清理（2.7 待确认）

### 组件 C：衔接点清单（本次需改动的文件与函数）
| 文件 | 函数 | 改动 |
|:--|:--|:--|
| `engine/evo/self_mirror.py` | `mirror()` | 末尾追加报告落盘（md+json，保留 30 份） |
| `engine/evo/arbiter.py` | `_apply_memory_weight()` | 每次调权追加一条 p6_audit.jsonl |
| `engine/call_diegin.py` | 无（不动） | — |
| `engine/evo/main.py` | 无（不动） | — |

> 说明：全部改动为「追加记录」性质，不改变仲裁结果；`fast_path=True` 时 P6 不执行，自然不产生审计记录（符合预期）。

4. 多副本同步：self_mirror.py + arbiter.py 同步至 4 副本，哈希一致

## 五、风险与边界

- 风险：极低。纯记录逻辑，不触碰 P0-P6 裁决分支、不改规则库、不阻塞主流程（所有 IO 均 try/except 包裹，失败静默降级）
- 边界：本批不实现 2.7 审计日志衰减、不实现 2.12 影子基线池计算、不实现 2.14 新鲜度指数计算——仅预留 `l1_pending` 挂载点与报告承载面
- 不触碰：`fast_path`（上批 L2 落地）、守三/攻七/一二不过三逻辑、规则库
