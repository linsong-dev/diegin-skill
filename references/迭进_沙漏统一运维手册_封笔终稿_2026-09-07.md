## 三、长期运行养护建议

### 3.1 自照镜休眠温启动策略
若自照镜连续跳过≥5次（或≥3天），下次触发时强制降级为"轻量校准模式"——仅对任务完成率/中断率做统计对比，不产出P6调权，只生成一份"唤醒报告"供用户审阅。该触发条件与守三状态解耦，仅由轮次计数驱动。

### 3.2 用户意图温度计
通过恒常门记录的intent_summary与当前对话语义的相似度，判断用户是否仍在同一任务轨道上。若相似度低于阈值（如0.5），预策律在"衡"阶段将此视为"意图漂移信号"，对应置信度上调或下调。

### 3.3 意图硬锚定
当意图一致性在连续3轮内低于0.6时，预策律暂停自动决策，强制生成意图确认请求，等待用户显式确认后再恢复。硬锚定期间，系统维持待机状态，不执行任何自动操作。

**超时处理**：当意图硬锚定持续超过10轮仍无用户响应时，自动退出硬锚定状态，采用"保守默认策略"继续运行，生成"意图确认超时"报告供用户后续查阅。保守默认策略指：在当前场景下选择置信度最高且历史成功率≥60%的规则执行，不进行任何冒险或创新性决策。

### 3.4 决策超时熔断
若预策律"衡"步骤耗时超过2秒，自动降级为"P0-P3硬优先级+最近一次P4/P6裁决"的快速通道，待低负载时再补全权衡。

### 3.5 P6影响审计日志
建立P6影响审计日志，记录每一次P6调权的来源（哪一次自照镜照见的哪一条规则）、幅度、以及该规则在后续几轮中的实际裁决变化。

### 3.6 守三时间戳衰减系数校准
对于高频变化的环境，建议将衰减系数调至×0.90或×0.85；对于变化缓慢的环境，可调至×0.98。

### 3.7 暂存区保留期校准
对于高频交互场景，建议缩短至"20轮或3日"；对于低频交互场景，可延长至"100轮或14日"。

### 3.8 审计日志衰减策略
P6影响审计日志保留期为90天或1000条记录（以先到者为准）。超期日志自动压缩为月度摘要，月度摘要保留12个月后自动归档至冷存储。

### 3.9 主动推进检查执行上限
每次主动推进检查最多验证1条Staging规则。若Staging池>1条，分轮次验证（每轮间隔≥3轮空闲窗口）。单次验证超时（>30秒）则自动中断。

### 3.10 参数调整记录规范
每次调整运维手册中的可配置参数时，须在日志中记录：调整人、调整时间、调整原因、预期影响。若检测到参数调整频率>3次/月，触发"参数扰动警告"。

### 3.11 快照分级存储检查
每月检查冷存储占用情况，若超过预设容量（如1GB/1000个任务），则触发自动清理策略——清理封存时间超过180天的快照，仅保留task_id和status。

### 3.12 "真理跌落"保护
当某条规则的置信度因守三多次下调而低于0.3，但去伪存真门在后续运行中接收到外部新证据，或"通外·纳新"通道出现与之强相关（余弦相似度>0.85）的新实证时，自动触发"规则复活听证"。

**听证门槛：**
- 若复活证据推导链长度为0（原始实证），支撑度≥0.6即可复活
- 若推导链长度≥1（经泛化），听证门槛下调为支撑度≥0.5
- 听证结果须在自照镜报告中标注，并记录至审计日志

### 3.13 听证泛滥防护
**场景：** 动态阈值松弛听证和规则复活听证并存，高噪声环境下可能频繁触发各级听证，导致系统在标准A和标准B之间反复横跳。

**养护建议：**
- 当任何形式的听证机制触发后，全局进入24小时听证冷却期
- 冷却期内，禁止触发其他类别的听证，优先让人工介入定调
- 冷却期内，系统维持当前有效的决策标准，不进行新的阈值调整或规则复活尝试
- 冷却期结束后，恢复正常听证机制

### 3.14 审计层自指熔断
**场景：** 当持行章在20轮内连续触发3次"规则沉积警告"或"振荡锁定"时，表明审计层本身可能已过度干预系统运行。

**养护建议：**
- 持行章自动进入"只读模式"
- 停止生成强制激活信号和阻断盲区反馈
- 仅保留侧压系数计算
- 只读模式期间，侧压系数触发阈值自动上调0.1（从>0.75上调至>0.85），降低资源压缩力度
- 生成审计层自指熔断报告，待人工介入评估
- 人工确认后，持行章恢复正常运行或调整审计规则

### 3.15 P1熔断恢复机制（静默锁止状态诊断 + ZOMBIE_RECOVERY）

**场景A：静默锁止状态诊断**
当一二不过三触发升级处理（三错锁剑落下），系统进入静默锁止状态（Level 3人工介入，24小时内无响应）。

- 系统进入静默锁止状态后，自动启动周期性只读诊断：每6小时执行一次环境健康检查（如API连通性、数据源可用性、网络状态），不执行任何操作，仅生成诊断报告。
- 若诊断发现环境已恢复（连续2次诊断通过），系统自动解除锁止并通知用户（发送"环境已恢复，已自动解除锁止"报告，等待用户确认后恢复运行）。
- 若连续3次诊断均无变化，维持锁止状态并提升告警级别（将"24小时无响应"升级为"人工介入超时，系统持续锁止"）。
- 诊断周期和次数上限可配置（默认6小时/3次）。

**场景B：ZOMBIE_RECOVERY逃生舱**
若系统锁止超过12小时且P1熔断恢复诊断连续3次通过（环境已恢复），允许系统以"极高风险标签"单次恢复。

- 恢复后自动生成紧急报告追加至审计日志并强制标记"ZOMBIE_RECOVERY"
- 该标签使该轮次所有决策置信度额外下调0.2
- **触发ZOMBIE_RECOVERY时，强制输出用户可见的红色警报级复苏叙事**：包含时间戳、锁止原因、恢复诊断结果、置信度下调幅度
- 用户确认"我知道你活过来了，请继续"后才启动恢复后的决策
- 若用户未确认，系统维持锁止状态，等待人工正式介入

### 3.16 侧压系数权重校准

侧压系数权重可根据部署环境调整：

| 场景类型 | 建议权重配置 | 说明 |
|:---|:---|:---|
| 标准场景 | 延迟0.3 + 快照0.25 + Token0.25 + 积压0.2 | 默认配置 |
| 延迟敏感场景 | 延迟0.4 + 快照0.2 + Token0.2 + 积压0.2 | 优先保障响应速度 |
| 存储敏感场景 | 延迟0.2 + 快照0.35 + Token0.25 + 积压0.2 | 优先释放存储资源 |
| 积压敏感场景 | 延迟0.2 + 快照0.2 + Token0.2 + 积压0.4 | 优先处理积压信号 |

### 3.17 外部数据源失能降级（P0级事件）

**场景：** 关键数据源（如API、数据库、外部服务）连续3次超时或返回异常格式数据。

**养护建议：**
- 当检测到关键数据源连续3次超时或返回异常时，自动触发P0级监测事件，系统进入"数据源降级模式"。
- 数据源降级模式期间，暂停所有依赖该数据源的决策，输出阻断报告，记录降级事件至审计日志，并立即通知人工介入。
- 当数据源恢复稳定（连续3次正常响应）后，系统自动解除降级模式，恢复正常运行。
- 触发阈值和恢复条件可配置（默认连续3次超时/异常触发，连续3次正常响应恢复）。

### 3.18 突变实验舱（anomaly_vault）管理

**场景：** 单次极端成功案例（置信度>4.8且历史相似场景成功率<30%）。

**养护建议：**
- 此类案例自动入舱，保留30天。
- 自照镜在轻量校准模式中，强制比对当前环境与舱内案例的环境特征（余弦距离）。
- 若高度相似（>0.8），直接生成一次性"探险信号"注入P4裁决。
- 探险信号有效期为当前轮次，不累积。
- 运维人员可定期审阅anomaly_vault内容，将已验证的突变案例手动转为规则。
- **守三冲突处理**：注入探险信号并执行时，临时挂起守三对该轮次该行为的strike记录。待轮次结束后根据最终目标完成度判定，决定该strike记录是否归档。

### 3.19 影子基线池更新协议（L1层）

影子基线池为安全锚点，其更新策略分为两种模式：

- **冻结模式（默认）**：部署时锁定，永久不变。适用于监管严格、需要固定安全边界的场景。
- **慢跟随模式**：每季度或每100轮，由人类审阅后决定是否更新基线池的锚定规则集。更新阈值为新规则在基线池对应场景中的表现连续优于旧基线≥10轮。

"优于"的评判采用三维框架（成功率、效率/收益、资源消耗），最终更新决策权保留给人类季度审阅。深侧放期间影子基线池不卸载。

### 3.20 小流量仿真验证协议

staging规则在正式固化前，增加3轮小流量仿真验证：

- 仿真条件：用户明确授权"进入仿真模式"，或系统处于空闲低负载窗口（侧压系数<0.3）——不依赖预策律的"低风险判定"
- 仿真量：仅影响≤10%的决策量
- 仿真期间若守三触发strike，规则自动退回staging并记录"仿真失败"
- 仿真期间若守三未触发strike且规则被命中≥1次，进入正式固化流程

### 3.21 熵寂警报与探索模式协议

**熵寂警报**：自照镜轻量校准模式中，统计三项指标——①近50轮内新规则入库数量；②staging池活跃度；③攻七高置信度模式产出频率。若三项指标在过去50轮内均持续低于历史均值的30%，自动生成"熵寂警报"（Level 2），固定输出至自照镜报告的"熵寂警报"章节。

**探索模式**：熵寂警报触发后，系统自动进入探索模式3轮：

- 探索范围：仅针对历史数据中置信度分布最稀疏的领域（系统最不自信的10%场景）
- 探索权重：预策律在保守默认策略与高风险泛化规则之间各投入50%的决策权重
- 保护机制：探索期产出的失败strike，不计入守三的"一二不过三"升级计数
- 代价审计：每次探索期结束后，自照镜强制生成《探索代价报告》，对比"探索带来的新收益"与"探索造成的附带损失"，作为下次探索模式触发的先决条件——若上次探索代价>收益，则本次探索权重减半
- **用户控制**：用户可在任何一轮通过明确指令中断探索模式
- **探索模式冷却期**：若连续3次探索代价>收益，则探索模式暂停触发，强制生成人工审阅请求，待人工确认后再恢复
- **深侧放状态触发的探索模式，其代价报告顺延至侧放解除后执行；冷却期从报告生成时开始计算，而非从探索结束时开始**


## 四、首次部署建议

迭进系统配置参数较多，新团队首次部署时建议按以下阶段渐进式接入：

| 阶段 | 范围 | 建议配置 | 目标 |
|:---|:---|:---|:---|
| **阶段1：核心闭环** | 攻七 + 守三 + 预策律 + 完形律 | 使用默认配置，不激活自照镜和持行章增强机制 | 验证基础学习-决策-封存链路 |
| **阶段2：加装审视层** | 激活自照镜（第九章） | 保持持行章默认配置，不启用振荡检测和强制激活 | 验证方向校准能力 |
| **阶段3：加装审计层** | 激活持行章增强机制 | 按默认参数运行，**上线前执行基线冻结**，持续观察状态检查表指标 | 验证资源管理和执行审计 |
| **阶段4：精调** | 根据运行数据调整各项阈值和权重 | 按养护建议逐项校准 | 优化系统表现 |

**阶段3基线冻结协议**：阶段3（激活持行章增强机制）上线前，强制触发一次"基线冻结"——将当前所有规则的置信度快照保存为"阶段2基线"。阶段3上线后连续观察10轮，若P6调权导致超过20%的规则置信度变动幅度>0.3，则自动回滚至阶段2配置，并生成冲突报告供人工审阅。若10轮观察期内未触发回滚，则基线冻结解除，阶段3配置正式生效。

## 六、故障排查指南

| 故障现象 | 可能原因 | 排查步骤 |
|:---|:---|:---|
| 系统无响应 | 守三深度复盘未退出 | 检查复盘进程是否异常阻塞 |
| 暂存规则长期未验证 | 主动推进检查未触发 | 检查staging池状态及空闲条件 |
| 某规则置信度持续下降 | 守三多次下调或自照镜同向干扰 | 检查应急复盘日志及审计日志 |
| 自照镜报告始终为空 | 守三深度复盘未触发且独立触发条件未满足 | 检查复盘计划任务及轮次计数 |
| 响应超时（>2秒） | 预策律"衡"负载过高 | 检查是否触发决策超时熔断 |
| P6调权频繁触及限幅 | 自照镜运行频率过高 | 检查最小运行间隔及应急触发频率 |
| 勇气信号始终未生效 | 用户未确认 | 检查用户反馈是否缺失 |
| 成功/失败判定频繁冲突 | 三重判断不一致 | 检查意图一致性计算或温度计校准 |
| **方向预判持续不准** | **预策律方向预判逻辑偏差** | **检查域判定规则及意图分类器** |
| **目标进度回撤** | **一二不过三熔断触发** | **检查目标层策略，重新评估可行性** |
| **攻七/守三状态标志超时驻留** | **异常中断导致状态标志未复位** | **检查模式驻留超时检测是否触发复位** |
| **守三下调与P6上调反复针对同一规则** | **自照镜方向调权与守三客观修正进入对抗循环** | **暂停P6对该规则调权 → 导出守三下调证据链 → 人工判断规则有效性 → 决定保留/修改/废弃** |
| **静默锁止状态持续超过24小时** | **P1熔断后人工未介入或环境未恢复** | **检查P1熔断恢复诊断报告 → 若环境已恢复则自动解除锁止 → 否则通知人工介入** |
| **深侧放频繁触发/退出** | **侧压系数在阈值附近震荡** | **检查延迟/快照/Token/积压各分量波动 → 考虑调整权重配置或提高触发阈值** |
| **侧放唤醒后上下文恢复不全** | **渐进式展开异常** | **检查RAG检索结果是否完整 → 检查恒常门指纹是否有效 → 必要时手动触发完整恢复** |
| **规则置信度高频震荡** | **多个负反馈回路同时作用** | **检查振荡检测器是否标记为振荡态 → 冻结修正 → 导出证据链 → 人工审阅** |
| **意图确认循环停滞** | **意图一致性持续低于阈值但用户未回应** | **检查意图硬锚定是否持续阻塞 → 超时后恢复默认保守决策 → 通知用户确认** |
| **数据源突然断流** | **外部API/数据库服务中断** | **检查数据源降级模式是否触发 → 检查连通性 → 确认恢复后自动解除降级** |
| **冷指针恢复后决策漂移** | **冷存储摘要丢失隐式约束** | **检查恢复漂移标记 → 触发去伪存真意图对齐 → 必要时手动加载完整快照** |
| **方向信号滞后导致误判** | **深侧放后方向信号已超有效窗口** | **检查P6调权时效性标记 → 超时信号自动失效 → 执行保守决策** |
| **ZOMBIE_RECOVERY触发** | **静默锁止逃生舱激活** | **检查审计日志中的ZOMBIE_RECOVERY标记 → 审阅恢复决策 → 决定是否保留后续规则** |
| **听证泛滥** | **高噪声环境频繁触发各级听证** | **检查全局听证冷却期是否生效 → 若冷却期内重复触发则拦截 → 优先人工介入定调** |
| **熵寂警报频繁触发** | **系统长期处于进化停滞状态** | **检查用户意图是否长期模糊 → 检查保守默认策略是否过度使用 → 考虑手动调整意图或触发探索模式** |
| **探索模式过度触发** | **系统频繁进入探索模式** | **检查探索代价报告 → 若上次探索代价>收益，探索权重自动减半 → 人工审阅是否需要调整探索触发阈值** |
| **审计层自指熔断触发** | **持行章过度干预导致自指熔断** | **检查持行章是否进入只读模式 → 审阅自指熔断报告 → 人工评估审计层规则 → 确认后恢复持行章正常功能** |


## 七、统一分层架构

| 层级 | 内容 | 可变性 | 修改/触发流程 |
|:---:|:---|:---:|:---|
| L0 | 九章·律令九章 + 沙漏动态架构（P0-P6硬优先级、原则结构、沙漏模型） | **不可变** | 不再修订 |
| L1 | 运维手册·骨（仲裁规则、基线池、指数、释法协议、侧压系数权重等结构级机制） | 可调，需人工确认 | 自照镜报告 → 人工确认 → 审计日志 → 生效；调整前须执行宪法解释协议 |
| L2 | 运维手册·关节（阈值、周期、衰减系数、侧压系数各分量权重等数字锚点） | 可调，无需每轮人工 | 运维团队按养护建议调整（记录参数变更日志） |
| L3 | 经验层（规则库/模式库/staging池/goal快照/案例原型库/anomaly_vault） | 持续进化 | 迭进自动运行 |
| L4 | 元规则管理（运维手册自修改协议） | 人工确认后可变 | 逻辑冲突 → 暂停 → 听证报告 → 人类确认 → 生效 |
| L0-L1 | 宪法解释协议（跨层冲突处理） | 人类确认后形成解释先例 | 冲突检测 → 一致性审查 → 暂停 → 宪法解释请求 → 人类指示 → 记录解释先例 |

**养护建议（第3章）层级归属说明**：养护建议属于L2层与L3层之间的过渡地带——其数字锚点（轮次、比例、天数）归L2，可调；其协议结构（谁触发、什么条件下触发）归L1，需人工确认后调整。养护建议的变更记录须纳入审计日志，但不自动触发系统行为变更。


## 八、未来扩展（非当前版本）

以下扩展项已记录，将在积累运行数据后评估纳入条件，当前版本不实施：

1. **索引预计算**：在守三/攻七入库时，预先计算规则与所有goal/domain的关联向量，降低实时检索延迟。
2. **勇气信号隐含确认**：若系统主动冒险后，用户未纠正且持续下达后续关联指令，赋予该冒险0.3-0.5的"隐含正向分"。当前版本保持显性确认以保守优先。
3. **资源感知降级（记忆轻载模式）**：当 Shalou 检索延迟超过500ms或审计日志大小超过阈值时，预策律主动降级为"记忆轻载模式"。
4. **行业基模吸收**：通外·纳新通道扩展至吸收行业基模（金融监管逻辑、医疗伦理边界等）。
5. **动态语义距离**：当规则库积累足够实证后，可评估引入"动态语义距离"——根据领域历史泛化成功率自适应调整阈值，或引入"语义距离+逻辑结构"双路判定。当前0.7阈值为保守设计。
