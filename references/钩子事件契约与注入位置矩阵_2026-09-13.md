## 一、一句话结论

> **注入点的「会不会 400（位置安全）」× 「会不会被压缩掉（存活期）」是两个独立维度。**

## 三、事件契约总表（12 事件 · 实测）

`hookSpecificOutput` = 平台唯一允许把内容送回模型上下文/权限决策的通道。
「可注入上下文」= 该事件的 `hookSpecificOutput` 是否含 `additionalContext` 字段。

| 事件（HookEventName） | hookSpecificOutput | 可注入上下文 | hookSpecificOutput 内其余可用字段 | 顶层可用字段 |
| :--- | :---: | :---: | :--- | :--- |
| `preToolUse` (PreToolUse) | ✅ | ✅ `additionalContext` | `permissionDecision`(allow/deny/ask)、`permissionDecisionReason`、`updatedInput`(保留字段) | `continue`、`decision`(approve/block)、`reason`、`stopReason`、`suppressOutput`、`systemMessage` |
| `permissionRequest` | ✅ | ❌ 无 | `decision` | `continue`、`stopReason`、`suppressOutput`、`systemMessage` |
| `postToolUse` (PostToolUse) | ✅ | ✅ `additionalContext` | `updatedMCPToolOutput` | `continue`、`decision`(block)、`reason`、`stopReason`、`suppressOutput`、`systemMessage` |
| `userPromptSubmit` | ✅ | ✅ `additionalContext` | — | `continue`、`decision`(block)、`reason`、`stopReason`、`suppressOutput`、`systemMessage` |
| `sessionStart` | ✅ | ✅ `additionalContext` | — | `continue`、`stopReason`、`suppressOutput`、`systemMessage` |
| `subagentStart` | ✅ | ✅ `additionalContext` | — | 同上 |
| `preCompact` | ❌ 无 | ❌ | — | `continue`、`stopReason`、`suppressOutput`、`systemMessage` |
| `postCompact` | ❌ 无 | ❌ | — | `continue`、`stopReason`、`suppressOutput`、`systemMessage` |
| `subagentStop` | ❌ 无 | ❌ | — | `continue`、`decision`(block)、`reason`、`stopReason`、`suppressOutput`、`systemMessage` |
| `stop` | ❌ 无 | ❌ | — | 同 `subagentStop`（`decision=block` 时 `reason` 语义必填，由解析器而非 schema 强制） |
| `interrupt` | ❌ 无 | ❌ | — | 仅 `systemMessage` |
| `sessionEnd` | 未取到 output 契约 | 推测 ❌ | — | — |

**三条硬事实（此前被误判的地方）：**

1. **`preToolUse` 的 `additionalContext` 是 schema 合法的**——它 400 不是因为字段非法，而是因为**位置非法**（见第四节）。禁用原因在位置，不在字段。
2. **`postToolUse` 的 `additionalContext` 同样 schema 合法**（`PostToolUseHookSpecificOutputWire`）——所以它仍是「唯一未实杀窗口」，不能因「PostCompact 不支持」就顺推 PostToolUse 也不支持。
3. **`preCompact` / `postCompact` / `stop` / `subagentStop` / `interrupt` 完全没有 `hookSpecificOutput`**——这些事件**在协议层就无法注入**，不是「我们没写」。

**附带发现（值得记入待办）：**

- `sessionStart.command.input.source` 的枚举是 `startup | resume | clear | compact`——即**压缩后会派发一次 `source=compact` 的 SessionStart**，而 SessionStart 支持 `additionalContext`。
  这是「压缩后补投」的**第二个候选点**，且处于边界位置的概率高。
  ⚠️ 但现有注册的 matcher 是 `startup|resume`，**未覆盖 `clear` / `compact`**；在完成第四节的实杀之前，**不得**放宽 matcher（否则等于在未验证位置注入）。

## 四、注入位置安全 × 存活期 二维矩阵

| 注入点 | 会不会 400（位置安全） | 存活期（抗压缩） | 当前处置 |
| :--- | :--- | :--- | :--- |
| `PreToolUse` | ❌ **致命**：钩子在 function_call 之后、function_call_output 之前触发，注入内容被平台插成 `message(developer)` 落在两者之间 → 上游 `400 No tool output found for tool call` | ✅ 长存（回合内一直可见） | **一律不再输出 additionalContext**（保留 `permissionDecision=deny` 阻断能力） |
| `UserPromptSubmit` | ✅ **安全**：回合边界（用户消息之后、模型回合之前） | ❌ 压缩即丢 | **当前主力**：行动时刻记忆投递点 |
| `PostToolUse` | ❓ **未实杀**：钩子在 function_call_output 之后触发，注入点落在合法边界之后 → 推测安全，但**未实测** | ✅ 长存 | **候选**，启用前必须过第五节清单 |
| `SessionStart` (`source=compact`) | ❓ 需确认是否发生在回合内；若在回合内则与 PreToolUse 同性质风险 | ✅ 压缩后立即重投 | **候选**，需先实测再放宽 matcher |
| `PostCompact` | — 协议层不支持注入 | — | 只能**重置闸门**，补投交给下一个安全边界 |
| `PreCompact` / `Stop` / `Interrupt` | — 协议层不支持注入 | — | 不用作注入点 |

**决策规则：**

- 需要「跨压缩存活」→ 只能在 `PostToolUse`（未验证）或 `SessionStart(compact)`（未验证）里选，且必须先实杀。
- 需要「绝对安全」→ 用 `UserPromptSubmit`，并接受「压缩后要等下一个用户消息」的延迟。
- 需要「压缩后立刻补投」→ 走 `PostCompact 重置闸门 + 下一个安全边界补投`（当前实现），不要试图在 PostCompact 里注入。

## 五、钩子注入安全检查清单（强制）

**任何新增或修改钩子 stdout 字段之前，逐条走完，不得跳步：**

1. **查 schema 是否允许该字段**——读 `codex.exe` 内嵌的 `<event>.command.output`；顶层 `additionalProperties: false`，写错字段名＝整个钩子输出被判非法（egress 失败），比注错位置更隐蔽。
2. **对照第三节表确认该事件是否有 `hookSpecificOutput`**——没有就到此为止，别设计注入。
3. **对照第四节判断该事件的触发位置**——落在 `function_call` 与 `function_call_output` 之间的，一律不得注入。
4. **在 `logs.db` 里实杀一轮**——用 `call_id` 精确配对（不是 `id`），断言「每条请求的 function_call 与 function_call_output 严格邻接、中间无 `message(developer)`」。
   证据源：`E:\项目\Codex_便携版\KeySync-Bridge\logs.db` → 表 `logs` → 列 `responses_input_history`（时间戳为 UTC、空格分隔）。
5. **查 `E:\项目\Codex_便携版\KeySync-Bridge\strip-proxy.log` 有无新增 400**，并隔离复跑钩子，断言 stdout 是**单个合法 JSON**。

> 事故教训：`additionalContext` 这个字段本身没错、schema 也允许，错的是它被平台插到了哪。**字段合法性 ≠ 位置合法性。**

## 六、待执行的两个实验（协议已备好，勿凭猜）

### 实验 A：`PostToolUse` 注入是否安全（唯一未赌窗口）

- **目的**：判定能否把 `PostToolUse.additionalContext` 用作「回合内长存」注入点。
- **前置**：在真正启用前，先造一个**只输出 `hookSpecificOutput.additionalContext` 单字段**的最小探针执行体，挂在 `PostToolUse`。
- **步骤**：
  1. 记录基线：当前 `strip-proxy.log` 行数 + `logs.db` 最近请求的 `call_id` 邻接结论。
  2. 启用探针（单独文件 + 开关文件控制，禁用时零输出），跑 **20 轮**含工具调用的回合。
  3. 复查：`strip-proxy.log` 有无新增 `400 No tool output found for tool call`；`logs.db` 邻接性是否被破坏。
  4. **判定**：无新增 400 且邻接完好 → 该窗口可用，压缩后能实时补投；否则**永久放弃**该点，只保留回合边界注入。
- **回滚**：删除开关文件即恢复零注入（不需改代码、不需重启）。

### 实验 B：`SessionStart(source=compact)` 是否落在安全边界

- **目的**：判定能否用「压缩后立即派发的 SessionStart」实现压缩即刻补投。
- **步骤**：
  1. **先只观察不注入**：把 SessionStart 钩子改为「`source=compact` 时只写审计日志」，同时把 matcher 临时放宽到 `startup|resume|compact`。
  2. 触发一次真实压缩（长上下文自动压缩，或用户手动 `/compact`）。
  3. 读审计：该次 SessionStart 是否在**回合内**被派发（与相邻 `PreToolUse`/`PostToolUse` 时间戳比对）。
  4. 若确认在回合边界 → 可启用注入；若在回合内 → 与 PreToolUse 同性质风险，**放弃注入，仅用于重置闸门**。

## 九、运维要点与本轮实测证据（2026-09-13 补）

### 9.1 工具链陷阱（都会伪装成「代码坏了」）

- **`sync.ps1` 必须用 Windows PowerShell 5.1（`powershell.exe`）运行**。`Get-Json` / `Write-JsonPretty` 依赖 `System.Web.Extensions` 的 `JavaScriptSerializer`，在 PowerShell 7（`pwsh`）下类型加载失败 → 自检出现 **7/10 的假失败**，`check` 打出成串 `OperationStopped`。
  - 正确：`powershell -NoProfile -ExecutionPolicy Bypass -File .\sync.ps1 self-test` → `10/10 passed`
  - 误用 `pwsh` 得到的 FAIL **不要拿去改代码**。
- **改 `.ps1`（UTF-8 带 BOM）的 BOM 双写陷阱**：用 `ReadAllBytes` + `UTF8Encoding.GetString` 读，BOM 会变成字符串首字符 U+FEFF；再按带 BOM 写回就成了**双 BOM** → PowerShell 把首行当命令跑，报 `The term '#' is not recognized`，但脚本其余部分仍会执行（症状极隐蔽）。
  - 正确：`[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)` 读（自动去 BOM）+ `UTF8Encoding($true)` 写。
- **判定 `sync.ps1` 是否真在比对**：看 `check` 打印的 `Src:` 与 `RT:` 是否为**不同路径**；相同即两副本被解析成同一路径 → 全量 `[OK] consistent` 的静默空转。

### 9.2 已知漂移（需人工定夺，勿自动同步）

- `律令九章_运维养护手册_2026-08-13.md`：源码库 9414 B / 运行版 10441 B，`sync.ps1 check` 报 `content differs`。
  这是**内容差异**（不是机器路径垃圾），**不应**加进 `known-excluded` 白名单（会掩盖真实丢失），也**不应**直接 `sync-refs`（方向未定，可能用旧盖新）。须人工比对后再定合并方向。
