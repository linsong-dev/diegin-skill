# AI 为什么总重复犯错？

> 一个 AI Agent 的系统性缺陷，以及一种把它根治掉的方式。
> 社区技术文 · 配套项目：[diegin-skill](https://github.com/linsong-dev/diegin-skill)

---

## 开头：同一个错，AI 会犯几次？

如果你长期使用 AI 写代码、做分析，下面这些场景大概率不陌生：

1. **编码问题反复踩坑**：同一个 UTF-8 / 转义 / 路径问题，上周犯过，这周换一个会话又来了；
2. **修好了这次，下次从零开始**：本轮明明修复成功，方法没有沉淀，下一轮 AI 又回到「从头试错」；
3. **偶然用对了的方法被忘掉**：成功只是运气，不构成可复用的知识；
4. **规则写了却像假的**：明明给 AI 写了规则，它却从不触发——规则存在，但等于没有。

这不是模型能力问题。换更强的模型，以上 4 条大概率照旧。因为根子在**系统结构**，不在单次推理。

## 一、根因：四个「没有」

### 1. 没有状态

会话结束后，行为经验随之消失。AI 对「上个会话怎么解决的」毫无记忆，每次都是「新员工第一天」。

### 2. 没有负向闭环

错误发生后，缺少「检测 → 归因 → 固化 → 验证」的自动链路。错误被修正，但修正本身没有被沉淀。

### 3. 没有正向闭环

成功只是偶然。做对的方法没有被识别、提炼、固化，下次可能又绕回错误路径。

### 4. 没有验证

即使写入了规则/记忆，也没有机制证明「它真的会生效」。规则可能引用不存在的字段、永远匹配不上——安静地失效。

> 一个真实的教训：我们曾实测规则库 active 规则中 200+ 条从未触发，其中 7 条 BOM 编码规则全部失效，导致同一个编码问题在 4 天里复发 4 次。规则写了，但「像假的」。

## 二、为什么单靠 Prompt 解决不了

Prompt / 系统提示词是**静态指令**：一次性约束行为，无状态、无闭环、不会自举进化。

向量记忆库 / RAG 解决的是**信息检索**，不等于行为约束——检索到了知识，AI 也不一定遵守。

LOOP 类循环（Reflexion 等）解决「**这一次**怎么做好」：执行→反馈→反思→再执行。但它循环结束经验即散，且很少固化成功经验。

真正缺的是一个**常驻的进化层**：在每次会话、每次工具调用背后持续运行——检测错误、固化修复、沉淀成功、跨域泛化、验证真伪。

## 三、律令九章：一种可运行的解法

「迭进（Diegin）」以**律令九章**（四律三门一锁一镜）构成一个互联的原则网络，干这件事：

| 章 | 别名 | 方向 | 一句话 |
|:-:|:--|:--|:--|
| 1 | 攻七 | 行知·正向强化 | 把验证过的正确做法提炼、固化、复用 |
| 2 | 守三 | 省知·负向纠错 | 检测错误、拦截风险、深度复盘 |
| 3 | 预策 | 裁决律·优先级宪法 | 原则冲突时按 P0-P6 硬优先级裁决 |
| 4 | 完形律 | 止观门·事毕封存 | 事毕清零、投入回收、不追加纠错 |
| 5 | 举一反三 | 通变门·跨域泛化 | 从个案提炼通则，经回归校验后激活 |
| 6 | 去伪存真 | 真伪门·验证 | 言必有证 → 证必可验 → 验证为真 |
| 7 | 恒常门 | 持存·跨会话续接 | 任务/经验跨对话持存，恢复不丢上下文 |
| 8 | 三错锁 | 安全阀 | ①错立改 → ②再错加固阻断 → ③三错升级处理 |
| 9 | 自照镜 | 方向校准 | 定期回望：方向是否偏、投入是否有效 |

### 三个最关键的设计

**① 错误要「升级」，不是重试（三错锁）**
- 第 1 次错：立即自动修复并验证（立改+改毕验）；
- 第 2 次同类错：归因过滤后写入硬阻断（内生惯性直接拦住）；
- 第 3 次：推翻原阻断方案、通知用户、系统升级。
- 效果：错误从「反复出现」变成「出现一次、被记住、被拦住」。

**② 成功也要沉淀（攻七）**
做对的方法被识别后：及时推荐（高置信度优先采用）→ 仲裁加权复用 → 跨域泛化 → 自动采纳反馈（采纳 +0.5 / 否决 ×0.7）。成功不再是运气，而是资产。

**③ 规则必须证明自己活着（去伪存真）**
- 写入门禁：trigger 引用不存在的字段 → 拒绝写入（确定性死规则）；
- 周期审查：active 超期从未触发的规则 → 死规则候选，分级处置；
- 验证原则：**「代码存在 ≠ 生效」**——`触发次数 > 0` + 审计日志有阻断记录，才算真生效。

**④ 跨会话不丢上下文（恒常门）**
任务在对话切换后自动恢复：目标/完成标准/待办三件套注入，不翻旧档案。当前引擎 241 个任务全部可跨对话续接，恢复率从 0 起步持续累积。

## 四、真实数据：它真的让错误不重犯吗？

以下数据来自迭进引擎 2026-08-21 实测（可复现）：

- **举一反三 ×2 当日 71/74 次命中、零误伤**：两条跨域泛化规则入库次日就在实战中大量触发，人工复核无误伤后保留发布；
- **image_url 守三 11 次审计**：某会话连续查看图片触发「三错锁」升级，当日 11 次命中全部按熔断设计处理，复查无复发即可解除；
- **攻七闭环 24 小时跑通**：入库规则次日即在实战中自动采纳（置信度 +0.5）；
- **死规则治理**：200+ 条死规则被揪出、触发验证门上线后，同类编码问题不再复发；
- **规则健康**：249 条规则三库一致（JSON/Mindol/运行时），死规则 0、空壳模式 0、假证据 0；
- **测试与自检**：引擎自检 failed_checks 全绿、test_all 32/32 通过；
- **记忆规模**：Mindol 2,111 条记忆单元、4.5MB SQLite 权威存储，时间衰减 + 自动休眠不无限膨胀。

## 五、边界与诚实声明

- 迭进提升的是**长期可靠性**，不承诺「永不犯错」——它让错误被检测、被固化、不再重犯；
- 引擎/契约异常时**一律放行业务**（标注未验证），不因进化层故障阻断用户工作；
- 规则引擎对结构化/半结构化任务收益最大；纯开放创作场景仍需人工裁决；
- 项目纯本地、零外部 API 依赖，数据不出本机。

## 结尾

AI Agent 进入生产环境的瓶颈，已经从「能不能做」转向「**可不可信**」。同一个错犯两次，再强的能力也难挽回信任。

进化层解决的不是单次任务的成败，而是**长期可靠性**——让 AI「错不重犯、对能复用、越用越聪明」。
