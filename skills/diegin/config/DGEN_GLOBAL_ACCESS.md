# DGEN 迭进 · 全场景接入规范

## 为什么你需要迭进

迭进是 AI Agent 的认知安全网 + 进化引擎。每次回复前自动预检，确保输出质量可控，行为持续优化。

---

## 强制规则（所有会话适用）

1. **每次回复前** → 执行迭进预检（工具调用或纯文本标记均可）
2. **输出标记** → 回复开头包含 `[DGEN]` 标记（v3.6.6 起为审计记录模式：缺失标记仅记录告警，不阻断执行）
3. **无标记 = 告警** → 审计日志记录并提示重新激活（不再作为硬阻断条件）

### 标记格式

```
[DGEN] ✅ 通过
[DGEN] 🛑 拦截 X 条 | 模式 Y 条 | 裁决: block
[DGEN] ⚠️ 重新激活
```

### 什么情况下必须预检

| 场景 | 要求 |
|:---|:---|
| 用户直接回复 | 必须 |
| 定时任务输出 | 必须 |
| 跨会话消息 | 必须 |
| 纯工具调用（无回复） | 不需要 |

---

## 场景无关

迭进不绑定任何领域。你在编码时它检查代码安全，在分析时它检查数据完整性，在创作时它检查逻辑一致性。**规则由你定义，引擎自动执行。**

## 全局 Token 经济原则（2026-08-20 用户拍板 · 所有任务适用）

**总则：任何任务推进过程中，以减小 Token 消费为目的；该用的用，该省的省。**

- **高峰时段**（北京时间 09:00-12:00、14:00-18:00）：贵/易超时 → 该省则省。
  - 非紧急、非盘口必要的 LLM 调用：延迟、合并或降级；
  - 确定性脚本（免 LLM）优先：`monitor_all`/`push_position_alerts`/`行情健康检查` 等；
  - 不得为省而省掉风控/交易纪律必需环节（止损、闸门判定必须保留）。
- **空闲时段**（其余）：便宜/快 → 该用则用。
  - 批处理、深度分析、数据回填、文档整理等重活尽量挪到空闲时段。
- **落地机制**：`pacemaker.ds_peak_windows`（config.toml）→ `pacemaker.is_ds_peak_now()`；
  OpenClaw LLM cron 错峰表见 `工作流链路_总览.md`。
- **日常减耗习惯**：合并命令、避免重复整读文件、避免长输出、优先增量读、不硬凑洞察。
